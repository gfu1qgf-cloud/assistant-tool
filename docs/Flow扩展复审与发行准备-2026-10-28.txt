2. 已验证并修复的安全问题
F1 高：网页通过原消息转发可调用不受限的 getStorage/setStorage，读取或覆盖 lzxConfig 配对令牌及主程序任务日志。
使用真实构建代码与合成存储离线复现，未接触真实令牌。本轮改为明确的 UI 状态 key 白名单，禁止通配读取和混合越权写入；仍允许上游设置、预设、任务 UI 状态保存。
F2 高：网页原生图片拖放原本只有扩展名检查，在 UI 互斥关闭时未独立验证本机图片路径。
现在必须存在主程序已鉴权上传指令建立的精确路径授权，并绑定标签页、项目、连接代次、有效期和请求；取消、匹配的完成消息、断线或项目变化使授权失效，实际输入前再次核验。
F3 中：网页 closeBrowser 消息可关闭此配置的全部浏览器窗口。
现在网页转发无权执行此操作，主程序已确认且满足原安全条件的关窗流程保留。
同时验证 runtime 消息来自本扩展、允许的 HTTPS 主机和顶层标签页；本扩展 ID 及 manifest 权限清单不变。
补丁独立于上游原件，使用唯一接入点校验；上游接入点改变时停止构建，不能静默跳过安全补丁。
前一份自审没有识别 F1/F2/F3，不应拿前一份结论代替本轮结果。无证据表明真实凭据已被利用，未擅自轮换令牌破坏现有连接。
本机仍在用的旧生成目录未热覆盖；源码模式正常重新启动主程序时按原受控更新机制切换。请等待任务空闲后更新并重新加载扩展，旧浏览器中已加载的脚本不会凭空获得修复。

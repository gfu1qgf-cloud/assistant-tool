# 视频压缩节点

位置：节点 → 处理与导出 → 视频压缩 · 编码设置。

节点传递统一视频流并记录最终编码设置，必须接到最终结算／导出／返回后处理结果。它本身不生成中间视频；带有编码设置的流不会被“未修改视频，跳过渲染”优化跳过。

## 你的截图配置

新节点默认 MP4、H.264、质量 CRF 30、MP3 128 kbps、Auto、立体声、44100 Hz；帧率、关键帧、画面尺寸默认不改。编码速度保留原默认 medium，因为截图未指定该项。

已有节点不静默覆盖已保存参数。选中后点击“应用截图配置 · H.264 30＋MP3 128”即可使用新配置，然后保存工作流。按钮只填参数，不锁定设置。

现有的 Shana “口播.xml”在检查时为 CRF 25 和 AAC，并不是本次截图的 CRF 30 和 MP3，因此没有把它当作截图配置导入，也不执行 Shana 的专有字幕滤镜。

## 参数面板

- 编码：MP4 输出说明、H.264／H.265、质量 CRF／固定量化器 QP／目标码率、编码速度。
- 画面：可选帧率、CFR、按秒指定关键帧、输出宽高及保持比例／补边／裁切／拉伸。
- 音频：MP3／AAC／保留原编码、音频码率、MP3 Auto／CBR／ABR、声道与采样率。
- 其他：Profile、Tune、快速起播、移除元数据及章节。

采用原生 Qt 实现，参考用户给出的分组布局，不复制 Shana 专有代码。当前输出仍由主程序统一保存为 MP4，不提供未实现的格式、OpenCL 或硬件编码开关。字幕、抠像、叠加、LUT 继续用现有节点，不另造一套。

## 如何判断压缩有效

完成日志显示实际编码参数和“输入大小 → 输出大小，减少／增大百分比”。文件来源、内存与管道传输都使用同一编码函数。合成／剪辑计划不拿完整源文件总大小冒充压缩率，只报告输出大小。

质量模式优先保持指定质量，并不保证任何已经很小的视频都再次变小。需要控制体积时选“目标码率”；这是平均目标，并非保证的最大文件大小。源文件保留，不自动用更小原件替换带有字幕、Logo或其他真实效果的成品。

Auto 对 MP3 使用指定码率与编码器默认码率模式；CBR／ABR 显式传入对应开关。保留原音频编码时，不偷偷重采样或改声道。拼接后的滤镜音轨不能复制编码时，使用 AAC 并在日志明确说明。

预览能反映画面尺寸和帧率处理，但单帧预览不是压缩后画质的实测；最终导出及大小日志用于确认实际编码结果。

参数依据：[FFmpeg 编码器文档](https://www.ffmpeg.org/ffmpeg-codecs.html)。

# 给协作 AI 的开发交接清单

[返回目录](README.md)

把任务说明、允许修改的插件和验收条件一起交给 AI，不让它仅凭旧聊天猜当前状态。

## 开始前

1. 读取仓库适用的开发约束、Git 状态、本插件入口、相关服务和测试；不要假设工作区干净。
2. 从 [接口地图](README.md) 定位真实实现，核对签名，不发明 `register_window` 等不存在的接口。
3. 写清楚本次是解释、诊断还是实现；不把诊断自动扩大成全面重构。
4. 明确数据边界、是否允许真实网络和付费测试。普通本地开发不授权提交生成或上传用户素材。

## 实现时

- 优先只改本插件；需要改宿主时说明缺少什么公共能力，不把插件 UI 和业务塞回 MainDialog。
- GUI 读取 → 纯输入快照 → 有界后台执行 → GUI 结果回调。后台不读当前项目/所选任务。
- 列出每个等待的超时和取消路径、每个资源槽位的释放路径、每种失败对下一任务的影响。
- 节点和预览只读参数，选择/刷新不改写参数；特殊效果有显式控制，预设不锁定用户能力。
- 付费重试分清“确定未提交”和“可能已提交”；后一种只恢复原结果，不盲目再生成。
- 私有数据使用受管存储；不写死盘符，不在日志、截图、工作流 JSON 或后台历史中保存密钥。
- 保留旧健康数据、用户未提交修改、任务归属及既有输出格式；必要迁移有版本且幂等。

## 验收与交付

1. 用至少一个实际 UI/调度调用链验证，不只测私有纯函数。
2. 测试失败、取消后再运行，旧回调与新任务同时到达，多项目并行和窗口关闭。
3. 说明哪些是真实库、哪些是假服务，是否有跳过/旧失败；没测在线业务就不要声称已实测真实账户。
4. 审查新增日志和文件输出，确保不泄密、不覆盖原任务，不生成无限缓存。
5. 更新用户说明、开发接口与回归测试；只提交本次文件，明确是否仅本地提交。

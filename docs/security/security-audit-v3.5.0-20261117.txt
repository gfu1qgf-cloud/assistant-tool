四、代码修复细节与攻击条件
C01：两个旧Google授权回调只设server.timeout，无法限制已接受TCP连接的读取；本地进程可连入后不发完整HTTP头，使取消和3分钟截止检查无法执行。新共享服务器为每个连接设置读超时和整次请求截止，防止持续滴送头部；超时后归还控制，不吞掉任意OSError。
显式开启SDK的S256 PKCE，保留state校验和127.0.0.1绑定，回调加no-store并只保留首个有效结果。只改登录保护，不更换账号、授权用途或令牌。
新增11项安全回归，覆盖无响应连接、整次截止、SDK真实PKCE参数、压缩包边界等；原Docs授权8项测试增加PKCE断言，未放宽业务检查。

C02：主任务ODS导入此前没有沿用表头编辑器的32MiB压缩／128MiB展开限制。恶意或错误表格可在进入行数处理前耗尽资源。现在先读取有上限的不可变快照、检查ZIP展开总量再交给odfpy，表头路径复用同一入口，避免检查路径后被替换。
odfpy当前使用defusedxml，未将此问题误报为已证实的XXE。128MiB限制仍不等于所有XML复杂度攻击已隔离，进程级解析时间／内存限制列后续建议。

C03：透明边界扫描与循环播放清单使用裸临时目录／路径写入，光标JSON缓存直接读删，固定人脸模型直接读取，绕过宿主数据检查。改为data_io/data_file；透明扫描的输出与错误日志也放在受检查的临时目录内。正常VeraCrypt会话保留原有保护，不偷偷回退系统临时目录。
无痕聊天的sqlite3.connect(':memory:')不接触磁盘，原静态规则误报；仅为字面量:memory:增加精确豁免，并测试普通路径、变量和URI数据库仍被检出。没有通过隐藏真实文件写入来“让测试变绿”。

C04：utility_managers中途导入插件UI，触发builtin导入库存插件，而后者又需要尚未定义的InventoryManagerDialog。改为模块__getattr__延迟兼容导入，旧导入路径保留；没有改变库存数据或插件默认状态。

误报甄别：两处MD5用于Google Drive传输校验而非安全认证，保留协议兼容并显式usedforsecurity=False；本地身份仍用SHA-256。SQLite动态列名／排序来自固定白名单，值使用占位符。Python节点exec属于经指纹确认的有意功能，外部导入／粘贴会清授权；子进程限时与数据限制不是通用安全沙箱。
下载与解压：核对Google下载HTTPS域名／重定向和文件名限制；FFmpeg/mpv先验固定SHA-256、仅提取明确文件名，不按任意归档路径落地。mpv下载总量／完整请求期限仍可进一步收紧。
TLS／序列化：未确认关闭证书校验、shell=True拼接、pickle反序列化或无界extractall的真实漏洞；静态无命中不是形式化证明。

R01：源码导入 Qt 正常，冻结 EXE 导入 QtCore 却报“找不到指定的程序”。
从 Analysis TOC 确认，PyInstaller 沿开发机 PATH 收进了其他工具的
icuuc.dll / icudt78.dll；该 DLL 缺少 Qt 需要的未加版本后缀的 ICU 导出，
系统 Windows ICU 则具有这些导出。不是凭文件名猜测，也不是 Qt 版本回退。
利用/触发条件：构建环境 PATH 含同名且不兼容的 DLL；若该目录可被攻击者
写入，也属于构建供应链风险。现在只对当前构建进程限定解释器与 Windows
目录，清除继承的 Qt/Python 路径覆盖；不修改用户系统 PATH、不替换系统 DLL。
重新构建后不再携带错误 ICU，实际 EXE 的 Qt/媒体/主窗口检查通过。

R02：仅运行源码测试不能发现上述交付问题。新增冻结 EXE 检查：使用独立
临时用户目录、空配置、离线模式与静音合成媒体；校验版本、首次引导、
26 个插件的主窗口加载、PyAV/OpenCV 解码、Pillow PNG、Torch CPU 运算、
Qt 视频帧与协作关闭。测试不注册全局热键，不使用真实账号或付费生成。
Windows 原生错误框被限定在检查进程内禁用，超时必须失败，不无限等待。
CI 显式从 PyTorch 官方 CPU 索引选择已验证的两个轮子；BUILD_INFO 拒绝
未经验证的 CPU/CUDA 变体，避免构建时静默更换原生组合。
官方安装来源：https://pytorch.org/get-started/locally/

测试失败甄别与修正（不是新增产品漏洞）
1. 64/3 路调度测试使用假编码器，却依赖真实剩余内存，可能被生产内存
   准入降并发。测试改用固定充足内存快照；低内存、等待、取消、重试仍由
   专用 13 项测试验证。生产内存保护未改。64 路仍断言峰值、72 项完整
   发布、无重复及返回任务顺序，不强制无关线程按启动顺序完成。
2. 抠像取消立即改名偶发 WinError 32。诊断未找到存活解码进程或 Windows
   报告的占用者；不能据此断言是杀毒软件或业务死锁。测试先核对原生线程
   与进程均退出，再在 1 秒上限内只重试 WinError 32；其他错误立即失败。
   五轮共 100 项通过。没有忽略清理异常、删除源文件或无限等待。
3. 第一轮两个真实媒体模块出现 30 秒超时，原日志保留；单独复验 60 项
   通过，第二轮全量中的相同模块亦通过。未加长生产超时或吞掉异常；
   首次超时的具体外部原因未证明，不写成“已确认系统负载造成”。
4. 第二轮仅视频拼接 UI 测试失败：在 QThread.finished 一发出即要求
   busy=false，而生产保护明确等待原生退出及 GUI 完成回调。测试改为
   12 秒内等待实际 busy 状态结束，期间处理 Qt 事件，并停止测试定时器。
   五轮共 120 项通过；输出、画面、音频、保护与按钮状态断言全部保留。

背景与边界
个人仓库 main 从旧版本快进后，新的完整 security-extended 扫描完成，
产生 25 条代码告警，而非 25 个已确认可利用漏洞。依赖图已自动刷新为
0 条开放依赖告警。正式标签尚未创建；本记录不冒充发布完成。
本轮 Flow 桥接升级为 1.1.63。原 release-validation 中的 1.1.62 EXE
与测试结果是前一候选的真实阶段记录；最终匹配包须重新构建并通过 CI。

加固详情与利用条件
批次 ID 原本已有 32 位十六进制校验，外部无法用 __proto__/constructor
穿过该校验；ACK 来自已认证桌面连接，原动态 delete 本身也不是原型写入。
仍改为 Map/own-key 明确数据语义，保持磁盘 JSON 格式、原子去重及请求
身份不变。未知/继承的 ACK 不写回，正确回执照常完成；不额外提交视频。
域名判断显式匹配完整主机或 '.flow.google.com' / '.labs.google' 边界，
拒绝 evilflow.google.com、notlabs.google 和真正域名后再拼接外域的情形。
控制台原始格式串拼网址可被 URL 中的 %c 等影响展示，但这不是 JS 执行。
改用常量格式与独立数据。日志换行已过滤；移除的只是冗余诊断参数，不是
素材选择、积分、生成、下载或人工控制功能。

本机通信误报的具体边界
options.js 中的 WebSocket 模板固定为 ws://127.0.0.1:<整数端口>。
setup ticket 限定 32 位十六进制；服务端仍验证扩展 Origin、票据、期限
与账号配置，长期 token 的领取不能绕过原校验。端口可配置是现有必要 IPC
功能；没有为消除扫描标记而锁死端口或移除用户连接功能。
不是把 URL 白名单改成不严谨的字符串 contains，也没有放宽 localhost 鉴权。

原始上游源码告警
third_party/flowcue/extension 的六个输入继续按固定 SHA-256 验证，未改字节。
其中 5 条对应本轮已改的日志/格式/域名代码，仅是供重建的上游原始输入，
不是主程序或扩展运行入口。构建器在复制后强制应用精确安全接缝；接缝数量
变化立即失败。程序与独立扩展只加载生成的 15 个白名单资源，源码包另附
构建器及补丁，不能把未执行的上游原件和生成后的代码混为同一漏洞。
复核后可按 false_positive 记录这些原件告警，附明确原因；不删除厂商原件、
不排除 CodeQL 扫描目录、不修改查询规则、不隐藏真实运行代码。

# VeraCrypt 加密与统一书签

## 启动与位置

1. 在 VeraCrypt 中手动挂载原卷，例如 Z 盘；密码只输入 VeraCrypt。
2. 首次使用根目录 `启动VC加密模式.cmd`，关闭旧软件实例后迁移，或选择已有数据。
3. 启用后，原来的正常启动方式也会要求选择卷；数据固定在该卷 `AssistantToolData`。
4. 未挂载、错误卷、只读、未知驱动版本、损坏标记或缺少主配置时拒绝启动，不创建空密钥配置。

盘符可以在不同次启动间改变；选择仍须通过原卷及数据身份验证，不依赖固定的Z盘。
已登记的25类私有配置位置保存为相对数据目录，读取时由主程序解析到本次挂载点；
旧版本已保存的绝对私有路径由统一存储映射重定位，不去访问原盘符。
库存头像、文案视频私有图片／缩略图也在读取时解析，原记录不因旧路径暂时失效而被清空。
这只覆盖完整的数据目录命名空间，不把任务／大型素材／视频输出的盘符随意替换；
运行中仍不能切换或重新挂载，卷中途失效后须正常重启，不回退旧盘或明文目录。

目前核对和本机实测的驱动是 Windows VeraCrypt 1.26.7。使用官方版本对应的只读查询结构，
再核对实际设备映射和目录句柄；卷标、盘符或伪造标记本身不作为加密依据。
以后更新 VC 驱动版本，需要先验证接口结构，不能绕过版本限制继续运行。

## 哪些数据搬迁

配置与 API Key/OAuth 凭据、主程序业务记录、插件私有数据、节点工作流、对话及附件、
图片/音乐/视频检索索引、私有缩略图、库存头像副本、完整日志及应用临时目录。
已登记的自定义私有位置映射到卷内，相关配置仅修改路径字段，不修改密钥或业务字段。

程序代码、公共模型权重、原始素材库、任务目录/任务表格和视频成品不自动搬迁。
外部浏览器及 Codex 客户端自己的活动配置仍由外部客户端管理；本软件的独立浏览器环境、
账号归档和书签库属于私有数据。不要将手动选择的任务输出目录误认为自动加密目录。

## 校验与恢复

迁移使用卷内临时目录，普通文件 SHA-256 校验，SQLite 使用包含已提交 WAL 数据的一致性快照并检查完整性。
SQLite 的 SHM 仅是易变的索引/锁信息，不能用其时间戳判断业务数据是否改变。外部 Codex 客户端
可能仍在更新的归档数据库按一致性快照保存，代表复制时刻；主程序的数据库及配置则要求停止写入后迁移。
未提交副本可以在核对目录归属和文件哈希后继续复制，不靠时间戳盲目信任旧副本。
目标已经存在时不覆盖；失败留下卷内副本供恢复，原数据不删除，也不新建卷外敏感备份。
`migration.manifest.json` 是最初迁移清单，日常运行修改数据后不能把旧哈希当成当前完整性证明。
本次实际迁移的全量复核结果位于 `migration.verification.json`。

若主配置损坏，请先关闭软件。可检查卷内 `migration.original-config.json`（仅路径被重写时生成）
或原程序目录仍保留的 `config.json`，并按迁移清单恢复私有路径；不要用示例配置覆盖真实密钥。
丢失卷或密码时本程序不能解密；原明文副本仍是本次保留的恢复来源，清理应另行确认。
不要删 `storage_bootstrap.json` 来临时绕过安全模式，否则可能重新使用旧明文状态。

## 运行与退出的限制

每次受管读写与数据库提交仍实时核对本卷身份/挂载代次/设备映射；不缓存几秒钟内的放行结论。
驱动版本在建立会话时校验，随后持有该驱动句柄，不对每条日志或SQL重开驱动、枚举其他卷和读取版本文件。
身份标记在校验后持有禁止写入及删除共享的只读句柄，程序运行时不可编辑/替换，退出后释放。
正常配置、凭据和业务文件并不因此被设为只读，也没有变更文件格式。

密盘健康与空间检查约每2秒在单个后台探测中执行；慢盘未返回时不会叠加线程或阻塞界面计时器。
配置热更新的定时文件探测也在后台读取，真正应用配置仍在主线程；内部保存后不采用更早的探测结果。
显式保存和退出保存仍在完成原子替换与冲突校验后才算成功，不以丢弃持久化换流畅。

卷失效后停止新提交、取消任务、关闭日志，并给中文提示；本进程不会自动恢复写入，重新挂载后应重启。
目录句柄减少普通卸载和改名风险，但**强制卸载可能打断第三方库原生操作，不能承诺所有竞态都消除**。
软件只关闭自身资源，不卸载任何用户挂载卷；程序崩溃或被强制结束后，卷也可能仍保持挂载。

实现核对：[VC 1.26.7官方驱动源码](https://github.com/veracrypt/VeraCrypt/blob/VeraCrypt_1.26.7/src/Driver/Ntdriver.c)
中的 `TC_IOCTL_GET_VOLUME_PROPERTIES` 按指定盘符查询当前虚拟卷和用户访问资格；未挂载时不返回成功属性。
本程序同时核对设备映射、卷ID与挂载代次，不把一次启动验证当作永久许可。

VC 保护卷未解锁时的磁盘数据，不约束已挂载时其他有权限进程。插件使用统一存储是开发规范，
不是恶意代码沙箱。操作系统交换/休眠文件、内存转储、外部缓存和旧 SSD 明文痕迹不在本方案保证范围内。
原明文文件及旧备份未删除，仍应妥善保护。日志在卷内，不自动导出或上传；分享前只选必要脱敏片段。

## 统一书签操作

入口：插件菜单“浏览器书签库…”或 Chrome 面板“统一书签库”。
可搜索、添加、打开、复制、删除软件中的书签；删除软件记录不自动修改浏览器。
导入扫描当前用户 Chrome/Edge 所有常见配置及账号书签、Firefox；便携版可手动添加目录。
去重保留路径/查询参数/片段的大小写和内容，不去掉网址参数；保留多来源标题和文件夹。
特殊协议书签只允许复制，不自动执行 `javascript:`、本地命令等内容。

清理流程是“导入并校验 → 关闭所有浏览器（含后台）→ 再次确认 → 卷内恢复副本校验 → 清理”。
源文件变化、有未导入书签、数据库格式未知、浏览器正在运行或 VC 不可用时不清理相应配置。
Firefox 的恢复快照包含完整 Places 数据库（可能含浏览历史），只保存在加密卷内，不上传。
浏览器原有 `.bak` / 自动备份不擅自删除；书签同步可能将删除传播到其他设备，或把云端书签重新下载。
软件不会自动关闭同步，也不能宣称云端副本已删除。

恢复最近批次时先关闭浏览器。检查恢复副本 SHA-256，且拒绝覆盖清理后发生变化的源数据。
失败批次的恢复副本仍保留；查看卷内 `PluginData/chrome_launcher/bookmarks/backups` 的结果记录，
不要盲目覆盖浏览器新数据。尚未清理或恢复副本不完整时，不伪报完成。

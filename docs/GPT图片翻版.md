# GPT 图片翻版 0.3.0

入口：插件 → GPT 图片翻版。凭据入口：程序设置 → GPT 图片翻版。

## 先创新提示词，再生图

新任务固定经过两个阶段：文字模型批量构思 → 校验并保存方案 → 图片模型逐个生成。默认文字模型为 `gpt-5-mini`，面板“提示词模型”可填写账号支持Responses与结构化输出的其他模型ID；不自动换模型。文字改写另有API费用，提交前明确确认。

每组最多10个版本，要求模型同时考虑组内差异，输出核心主题、保留项、每个版本的构思、具体变化维度和完整新提示词。大任务分组处理，已接受构思参与后续即时组的去重提示；Batch分组并行，因此不声称每组能读取其他组的实时结果。跨组收到后仍校验重复。

- 低创新要求保留主题、场景和动作，以镜头变化为主；80以上要求至少三个具体变化维度，包含场景或动作；100要求场景、动作、构图以及至少另一个维度。
- 重复编号、缺方案、重复或高度相似提示词、过于接近原文的高创新文本、拒绝／截断响应都会阻止生图；不会用旧模板静默兜底，也不自动反复付费重写。
- 生图只使用改写后的完整描述和人物身份约束，不再附加完整原文、固定六个角度或“请自行创新”的口号。参考图仍只在生图阶段上传，文字创新阶段不上传图片。
- 原文、文字请求、响应、用量、构思、变化说明及最终提示词保存在私有插件存储。右键“查看提示词与错误详情”可核对各版本；成品JSON包含对应创意方案。文本校验不是图像语义质检，仍需人工判断成品是否足够创新。
- 即时模式：文字阶段也用普通接口，完成全部方案后自动生图；已经接受的方案不重复改写。文字请求结果不明时暂停，可右键“重试失败／未确认的提示词创新”，但会提示可能重复文字费用。
- Batch模式：先提交文字Responses Batch，确认所有方案有效后才提交图片Batch；两步均按对应Batch计费，可能需要两轮24小时处理窗口。文字Batch响应不明时查询／关联原批次，不自动再提交。
- 旧任务保持原有已冻结提示词，不追溯增加改写费用；用旧参数另做新任务时会走新流程并重新确认费用。首次保存新两阶段任务会将插件数据库版本标为3，旧版拒绝打开，避免绕过改写阶段；更新后正常重启再使用。

## 使用

1. 选择提交方式和提示词文字模型。新界面默认即时，旧草稿缺方式时保持Batch。填写原始提示词，设置数量、创新程度、比例、质量及图片模型。
2. 如需保持固定人物形象，添加最多4张本地参考图；缩略图可双击查看完整画面，右键移除。没有参考图就是纯文字生图。
3. 选择输出目录，点击“生成 · 即时提交”或“生成 · 提交Batch”，核对数量、模型、参考图上传与相应计费提示后确认。即时模式明确提示不享受Batch折扣。
4. 程序先持久化输入，再后台处理参考图并提交。原始／最终提示词、参数、参考快照、执行身份与逐张映射保留。关闭面板不取消。Batch云端等待不占本地工作线程；即时模式有当前网络请求时需安全收尾，不承诺瞬时退出。下次启动恢复记录，不重发结果不明的请求。
5. 有活动任务时每5分钟检查，也可以点击“检查并收取结果”。待处理错误累计3次会暂停自动检查该项，修正路径／网络等问题后手动检查恢复；不会因此阻塞其他记录。

历史列表右键：查看详情、打开目录、沿用参数、重试失败项、停止／取消、删除结束记录。即时模式增加“仅继续尚未提交图片”，以及需额外确认的“重试未确认图片（可能重复计费）”。Batch保留“关联控制台批次ID”，不能拿Batch ID接管即时请求。

## 即时生成（非Batch）

- 直接调用官方图片生成／编辑接口，逐张提交，不进入Batch的24小时队列；实际速度仍受模型、分辨率、质量、账号限流及网络影响。
- 每完成一张立即校验落盘并更新预览与“已收取 x/y”。每轮只处理一张，再由宿主继续下一轮，其他Batch的检查链不被改成普通计费。
- 当前请求发送前保存逐张意图；收到完整响应后先保存临时回执，再校验和写PNG。写文件失败时恢复回执，不重新生图。PNG及元数据确认保存后清理临时回执，避免长期双份图片占空间。
- 超时、断线或强制退出可能使当前请求结果不明；普通图片接口没有承诺按本地任务ID找回结果的能力，因此标为“提交待核对”，不自动重发。可仅继续没发送过的图片；若明确选择重试未确认图片，会警告可能重复计费。
- 额度、授权、参数等明确错误暂停该任务，避免后续数百张重复失败。成功图片保留，修正后从右键菜单继续／重试；不会因此阻塞其他任务。
- “停止后续图片”可在当前请求仍进行时使用：停止标记独立持久化，不强杀线程；当前已发请求可能仍计费，正常返回后仍保存，后续图片不再提交。重新打开面板不会自动撤销停止标记。
- 网络连接超时10秒，即时生成读取超时180秒；Batch及文件管理维持原读取超时60秒。网络超时不等于官方已取消生成。
- 更新后须正常重启再使用新面板，界面会拒绝与仍在运行的旧提交器混用。首次保存即时任务会把插件数据库版本标为2；旧0.1版本会拒绝打开，不会在降级后误把即时记录当Batch重新提交。仅有旧Batch记录时不升级该标记。

## 创新程度

- 0：忠实呈现原始提示词，只允许轻微镜头变化。
- 1—30：主要改变机位、景别、构图及轻微光线，保留主题、场景和物件。
- 31—70：保留核心主题与人物关系，重新设计动作、细节、机位与光线。
- 71—100：保留核心寓意，明显重构场景与视觉表达。

创新是文字模型的改写策略，不是图片API原生参数，也不是可精确保证的差异百分比。先生成具体新方案，再交给图片模型；有参考图时，人物身份要求不随创新程度放开，实际一致性仍需人工检查。

## 费用与恢复

两种方式均只访问官方API。即时模式直接POST `/v1/images/generations` 或JSON `/v1/images/edits`；Batch通过 `/v1/batches` 提交相同端点的批处理。提供 `gpt-image-2.5-flare` 与 `gpt-image-2.5-sunburst`；具体权限由官方确认，拒绝时不偷偷换模型或计费方式。

每批1—500张，每张一条请求、固定 `n=1`。使用独立的 `custom_id`，结果不依赖返回顺序；每次重试生成新尝试ID，只包含已确认失败的图片。成功结果不会因为重试而重做。

Batch处理窗口为24小时，按官方Batch价计费；即时模式按标准价计费。均按实际用量，不保证赠送额度适用具体账户，不提供未经核验的固定价格。两种方式不会因失败自动互换；已执行部分仍可能计费。

网络超时或提交响应损坏时，先保存“提交待核对”，按元数据查询原批次；没有查到不等于没扣费，不自动提交第二次。已结束批次的下载错误仅重新读取原结果文件，不触发生图。部分结果损坏也会先收取其他健康图片。整批过期／失败时保留成功部分，其余明确标为失败；只在用户确认后重做。

OpenAI Key复用宿主加密密钥池；作业仅记录不可逆凭据身份，不保存Key。更换当前Key不影响老批次查询；删除原Key会使旧批次无法访问，需恢复原Key。不会尝试别的账户来重新生成。

## 保存位置与隐私

- 作业数据库、草稿与人物参考图快照：宿主管理的 `PluginData/image_remix/`，随当前私有／加密存储，不写死盘符。
- 成品：用户指定目录下独立的 `图片翻版_时间_ID/` 子目录。每张PNG附同名JSON，记录提示词、模型、批次及用量（如果API返回）。不会覆盖输入图片；输出文件同名但内容不同时保留原文件并报错。
- 人物参考图会上传OpenAI，上传前有确认。参考图规范化到不超过2048边长；上传文件设置7天到期。云端批次输出需及时收取，官方输出文件有保留期限。
- 关闭窗口保存草稿；删除本地结束记录不删除生成图片及参考快照。活动批次不允许直接丢记录，避免失去已付费任务的恢复依据。

依据：[结构化输出](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)、[Batch API](https://developers.openai.com/api/docs/guides/batch)、[JSON图片编辑](https://developers.openai.com/api/reference/resources/images/methods/edit)、[文件上传与到期策略](https://developers.openai.com/api/reference/resources/files/methods/create)。

本轮验证仅使用隔离临时数据及模拟API响应，禁止真实网络请求；未调用用户Key生成收费图片，不把离线测试等同于真实账户验收。

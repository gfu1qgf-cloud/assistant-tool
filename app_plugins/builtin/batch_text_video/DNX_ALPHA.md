# DNxHR 原生透明通道

DNxHR MOV 可以包含 Alpha，而当前随程序提供的 FFmpeg 只读取颜色。1.45 自动识别压缩帧头中的 Alpha 标志，由独立原生进程读取原始 Alpha；颜色仍直接来自原 MOV。不会重新抠图，不使用滤色模拟透明，不调用达芬奇，不生成第二份 RGB／透明 MOV。

- 导入与设计图：只解选中帧的 Alpha，小型临时文件随即删除，不为首帧预览处理整段视频。
- 播放／导出：首次建立无损灰度 FFV1 遮罩，之后复用；原 RGB 不转码。输入索引同时计入额外遮罩及增强抠像的画笔遮罩。
- 循环叠化、工作台原图／AI 预览和视觉节点使用相同 Alpha。遮罩与 RGB 按帧编号重建相同时钟，避开 MKV 毫秒时间基造成的错帧。
- 缓存位于 `%LOCALAPPDATA%/AssistantTool/BatchTextVideoPreview/dnx-alpha`，禁止落入绑定加密卷。单个遮罩上限 128 MiB，空闲缓存按 512 MiB 清理；使用中的文件保持租约，全部释放后再回收，因此活动渲染期间可能暂超空闲上限。
- 同一素材并发只建立一次，进程间也有构建锁；最多同时准备两段不同素材。取消、错误及源文件改变不发布半成品。中断残留仅在超过一小时且无构建者持锁时清理；不删除源素材和成品。

当前兼容层接受逐行、固定帧率、直通 Alpha 的 DNxHR MOV。已用实际 DNxHR SQ／8 位／DCT Alpha／1920×1080／30fps／301 帧素材验证。预乘 Alpha、交错 DNxHD、变帧率、带裁切／旋转的 DNxHR Alpha 会明确报错，不将不支持的透明素材当成不透明画面继续渲染。其他 DNxHR 变体尚缺少独立参考样本，不宣称与达芬奇逐像素一致。已有 CineForm／ProRes／QTRLE 等由 FFmpeg 原生支持的透明格式沿用原解码。

原生程序及可重建源码、固定依赖、许可证见 `native/`；运行时不安装编译器、不联网、不下载模型。

# 普通／增强颜色抠像

入口：批量文案视频 → 图层 → 选择图片或GIF／视频组件 → 视觉效果 → 叠加与抠像。
节点工作流中的“添加图片”和“添加GIF／视频”共用这套设置。

## 普通

选择绿色／蓝色／黑色预设，或在“基准颜色”选择任意颜色、输入 `#RRGGBB`。
颜色改变后自动选择自定义预设。按颜色容差、边缘柔化和透明度双端修正扣除。
“边缘柔化”0–1是归一化强度，只控制抠像颜色附近的窄过渡带；0为硬边，1为最柔。
内部统一映射为0–0.1的RGB距离宽度，避免将界面数值直接传作整幅颜色距离范围，造成主体整体发虚。
颜色容差仍决定被扣除的颜色，素材自身透明度、图层不透明度及透明度双端修正独立生效。
静态预览、播放／导出和节点使用同一映射；已有柔化数值保持不变，新渲染采用修正后的强度解释。
旧项目默认普通，原预设、容差、阈值和去色溢开关不变；不改写配置文件或源素材。
去色溢目前只适用于以绿／蓝为主的基准色，其他颜色不会错误套用绿／蓝去色溢。
静态预览和原生渲染使用同一保守规则：只将抠像色通道中超过另外两通道最大值的部分压低。
不因打开绿幕去色溢就削掉肤色、米白衣服中的正常绿色；蓝幕处理蓝通道，不削绿。

## 增强 · 轮廓保护

逐帧以颜色得到初步透明度，再识别与画面四周连通的背景。
默认保护轮廓内封闭的同色区域，因此衣服内部的绿色装饰可以保留，不再见绿就扣。
去色溢只作用于未保护区域，保留保护区原RGB颜色；素材原透明度和控件不透明度仍独立有效。
可关闭“保护轮廓内封闭的同色装饰”，仅使用辅助遮罩。

这是区域／轮廓算法，不是人物语义识别，也不保证任何绿色饰品都被自动识别。
同色装饰若与背景连成一片，自动区域分析无法区分；手臂围成的真实背景孔洞也可能被保留。
两腿间、手臂外侧等通向画面边缘的凹口仍被去除，不采用会填平这些凹口的凸包包裹。
不要把它用于要求保留烟雾／火花／玻璃等天然半透明细节的素材而不检查成品。

### 可选辅助遮罩（trimap）

- 白色（255）：保护主体，不受颜色抠像和去色溢破坏。
- 黑色（0）：强制去除，可清除被自动填上的真实背景孔洞。
- 中灰（128）：不干预，沿用自动结果。
- 其他灰度：渐变干预；遮罩本身透明的地方不干预。

支持图片、GIF和本地视频，只读取、不上传、不改写。按原叠加素材的整幅画面缩放，并保留素材自身透明度；推荐使用同画幅、同时间轴的遮罩。
静态遮罩固定在素材坐标；运动饰品需要相应的动画遮罩。动态遮罩从0秒开始循环，独立于素材循环设置；视觉素材关闭循环后仍在播完时隐藏，不因遮罩循环而冻结最后一帧。
节点的可选“增强辅助遮罩”输入端可传文件路径，优先于面板里填写的路径；仅增强并开启抠像时生效。
原遮罩路径的文件戳纳入节点资源检查和播放预览缓存，文件变化需要重新预览／提交；不静默使用失效文件。

首帧用OpenCV的四邻域洪泛识别，完整播放和正式输出由FFmpeg的同一套原生滤镜逐帧处理。
不下载AI模型，不逐帧调用Python视频渲染，不产生完整抠像中间视频；最终合成仍只进行一次视频编码。
首帧是编辑示意；视频动作、出入场、孔洞和遮罩效果应通过“播放预览”核对。

算法参考：[FFmpeg floodfill](https://ffmpeg.org/ffmpeg-filters.html#floodfill)、
[OpenCV floodFill](https://docs.opencv.org/4.5.1/d7/d1b/group__imgproc__misc.html)。

# Antigravity 多账号切换（试用）

入口：主程序 **插件 → Antigravity 多账号切换…**。无需安装 Chrome 扩展，不是 FlowCue。插件管理沿用主程序现有入口；禁用后下次启动不提供此插件命令。

## 1.3：Antigravity 2.x 桌面版与旧 IDE 分开适配

- 修复已确认的错源：2.24 桌面版使用 `resources/app.asar`，不带旧 IDE 的 `resources/app/product.json`；不能把它误当残留安装，再退回读取另一套 IDE。现在只读验证 ASAR 中的产品名、包内Google作者标识、主入口及受支持版本；这是格式确认，不是代码签名验证。未知的正在运行版本直接报错，不改读旧账号。
- 桌面版从 Windows 凭据管理器中唯一已确认条目 `gemini:antigravity` 读取。邮箱来自其中 Google ID Token 的明确 email 字段，不搜索任意字符串。界面仍标明是本地登录记录，未联网验证令牌或JWT签名；不会把解码成功宣传成在线验证成功。
- 检测、受管存档、用户主动绑定／切换和恢复均使用同一来源；新版小型账号档案只包含该条目及必要的写回元数据。档案仍经主程序私有存储接口保存到当前VC卷，旧 IDE 档案不混入、不迁移、不删除。
- 新版账号是当前 Windows 用户的系统条目，不因 Electron `--user-data-dir` 隔离。面板明确显示这一来源；不枚举或操作其他系统凭据。不复制整个 `.gemini`、会话、历史、缓存或项目。
- 只有用户确认切换／首次绑定后，且所选客户端及其专用 `language_server.exe` 均已退出，才允许写入／清空此条目。复用原事务与受管恢复快照，写入后再核对；失败回滚，回滚失败保留恢复记录。刷新和账号检测绝不写系统凭据。
- 每次重新打开面板重新检查运行来源，不固守此前选中的旧 IDE；无法确认时隐藏过期窗口，检测失败不继续显示过期邮箱。

Win32接口依据：[CredReadW](https://learn.microsoft.com/en-us/windows/win32/api/wincred/nf-wincred-credreadw)、[CredWriteW](https://learn.microsoft.com/en-us/windows/win32/api/wincred/nf-wincred-credwritew)。没有修改 Antigravity 安装包或其认证实现。

## 1.2 账号识别修正

- 不再把数据目录固定成 `%APPDATA%/Antigravity`。根据已验证产品的名称、实际运行的可执行文件及 `--user-data-dir` 确定来源，支持 Antigravity IDE 与便携用户目录。读取数据库、保存档案、正常关闭及再次启动绑定为同一目标。多个空闲客户端且没有明确选择时，不默认选择第一项。
- 面板顶部显示客户端下拉框和完整检测路径。可以明确切换客户端；不关闭另一套安装或同一安装的其他用户数据环境。
- 邮箱只来自 `userStatusSentinelKey` 内 `UserStatus.email` 的第7字段，姓名来自第3字段。删除把二进制按换行分割、在整块内容中搜索邮箱和套餐的旧做法；嵌入的支持邮箱、其他主题和重复身份不再作为当前账号。未知格式明确报错，不猜测。
- 表格始终显示档案自己的邮箱，当前客户端缓存账号另行显示。只有两者邮箱确实一致才显示一致标记，不因索引中的“活跃档案ID”就声称正在使用该账号。
- 每个客户端／用户数据位置使用独立加密档案子库。1.1旧仓库没有绑定可靠来源，继续原样保留，不自动继承为新客户端账号；面板会提示重新核对来源并保存当前账号，不删除或迁移旧档案。
- 本轮已在本机 Antigravity IDE 的真实缓存上只读确认解析格式和脱敏身份；没有停止客户端、调用Google接口或执行账号切换。实际登录是否过期仍不能由本地缓存判定。

首次使用：

1. 在 Antigravity 中正常登录自己的现有账号，回插件点“保存当前账号为首个档案”。这是只读读取客户端登录记录、写入受管账号仓库，不会切换当前账号。
2. 点“＋ 添加新账号”，选中后点“首次登录/绑定此账号”。先保存 Antigravity 中的工作；确认后插件尝试正常关闭客户端，新版仅清理已确认的专用系统凭据条目，旧IDE仅清理本次支持的四项登录记录，再打开客户端。
3. 在客户端自行完成 Google 登录，回插件点“刷新状态”保存新档案。未发现登录或无法确认新邮箱时，不会假装绑定完成；仍登录原账号时，不会把原账号误存为新账号。
4. 已绑定账号可选中后切换，或切到下一个就绪账号。切换、等待客户端退出在独立线程执行，不强杀进程。不能正常退出就不修改登录记录。

存储和恢复：

- 账号仓库使用 `context.storage` 下的 `accounts`，随当前受管私有数据位置／VC卷改变，不写死 Z 盘，不另建用户目录明文仓库。索引内是相对凭据目录。
- 旧IDE只保存 `oauthToken`、`userStatus`、`modelCredits`、`profileUrl` 四个明确键的小型SQLite档案；新版保存上述专用系统凭据的小型受管档案。不复制整个客户端数据库、聊天、工作区或大缓存。读取IDE源数据库使用只读SQLite事务，包含已提交WAL内容，不直接复制活数据库文件。
- Antigravity 自身的登录数据库仍位于它的原目录；本插件不声称把外部客户端全部加密。
- 切换有受管恢复快照和事务记录。自动回滚失败会明确报错并保留记录；再次打开插件不擅自覆盖运行中客户端，用户可在退出客户端后点“恢复上次未完成的切换”。归档账号不删除其凭据。
- 旧版未接入源码若曾独立创建 `.antigravity-account-switcher`，本轮不自动迁移或删除。需要另行校验迁移，不能直接改索引路径。

限制：当前只检测本地缓存中的邮箱／套餐字段，**不联网确认Token有效性，也不查询实时剩余额度**。未识别到的字段显示未知；本地存在Token不等于尚未过期。账号结构、系统密钥链或客户端版本变化可能导致切换后需重新登录，这时通过官方客户端正常登录后再刷新；不做额度绕过、设备伪装或自动注册。

1.3采用合成账号、模拟Win32接口／进程和隔离Qt窗口测试，另对真实2.24的产品、系统登录记录做只读对照，仅输出脱敏邮箱和与用户截图是否一致的布尔结果。没有存档／改写真实Token、调用Google接口、停止用户进程或执行真实账号切换。正式源码不热重载，正常重启辅助工具后使用修复。

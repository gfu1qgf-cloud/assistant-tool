主插件 0.4.22／扩展 1.1.19：账号余额低于 10 积分时持久冷却 6 小时，同账号窗口、重连和重启共享。期间不自动打开、检测积分、修复页面或提交新任务；10 积分仍可用于费用不高于余额的任务。冷却到期且有可执行队列时重新检测，手动积分检测／顶部刷新可提前确认；仅成功读到至少 10 积分才提前解除，失败或仍不足 10 保留冷却。普通正余额不增加几分钟的过期轮询。浏览器表显示记录余额、冷却状态和截止时间。

协议协调与队列运行在独立 Qt 工作线程；界面只发送命令和接收快照。主机存储接口创建 `queue.sqlite3` 与 `pairing.json`，SQLite 连接按事务显式关闭。媒体归档在线程池中处理，输出由提交时的任务目录和文件名快照决定。

`store.py`：输入快照、持久队列与调度约束。
`service.py`：本地认证、账号积分、状态机、有限配置启动及归档调度。
`archive.py`：下载归属校验、FFprobe 验证、复制与同名保护。
`plugin.py`：平台注册、Qt 生命周期与 Chrome 启动器协作。
`ui.py`：图片／提示词提交、全局队列、账号和连接设置。
`submission_ui.py`：手动逐条提示词、任务图片完整预览和生成参数组件。
`manual_panel.py`：逐图持久草稿、成功回执后切图、最近提交及逐成品回看。
`policy.py`／`operations.py`：可负担性、等待原因、浏览器环境隔离、停滞核对和下载暂存恢复。
`queue_ui.py`／`result_preview.py`：分组筛选、多项编辑、批次预算入口及公共播放器预览。
`routing.py`：浏览器时长分档与费用组合键；不硬编码网站价格或账号可生成条数。
`setup_support.py`／`setup_ui.py`：单配置连接向导、只读安装检测、明确项目绑定与临时剪贴板准备；不修改 Chrome 安全配置。
`setup_pairing.py`：已验证扩展来源的单次／限时本机连接票据；票据与配置／项目绑定，配置保存后自动在扩展页领取并保存。只在用户显式进入选择项目步骤时识别剪贴板项目链接；备用复制按钮可见，缺少有效地址时禁用。
`connection_status.py`：统一的连接／页面／账号积分就绪状态和可自动启动配置筛选；不把保存地址当作页面在线证据。
`pricing.py`：用户明确指定的 Omni 固定时长费用；估算、调度和预留共用，不混入页面观测缓存。
`transfer_policy.py`／`transfer_retry.py`：持久化的上传／下载阶段退避、限次、原绑定恢复及重试状态；仅发传输和查询请求，不发送生成请求。
`media_identity.py`：只认生成请求响应建立的提交／任务／媒体绑定；下载通知与归档入口均重新核对，不凭文件存在、提示词相似或页面上只有一个视频推断归属。

队列记录删除由 `QueueStore.delete_records()` 事务处理，界面多选／快捷键只发命令。后台重查执行／保存状态，忙碌项保留；不删除媒体或草稿，不退还批次预留，保留最小去重标识以安全处理迟到回包。

手动放行 ID 仅保留于当前会话，任务快照持久保存。后台暂停时仅调度用户明确放行的条目；重启不会自动恢复这些放行，网站安全暂停也不会被新提交绕过。批量／手动保存按来源与请求 ID 分别确认，互不清空草稿。

时长分档保存在队列数据库设置中，按 Chrome 配置目录标识；未填写目录的已连接扩展使用稳定浏览器 ID。默认自动管理：已有同档优先、通用档次选、空闲自动配置改档兜底；全队列先比较匹配等级，避免把已有同档任务的浏览器抢走。显式手动更改写入 `*_lane_modes=fixed`；旧版首次自动写入的档位保持自动。忙碌浏览器／同账号、待核对和下载未完成项不重新分配。

`credit_policy.py`：每次连接首次读到余额后采用会话本地账本，在发送付费请求前保守扣算，同账号窗口共享；取消周期和逐次菜单查询。显式刷新／重连可校正，不确定结果不自动退款。扩展被动观察账号变化，不为每次核对弹账号菜单。

构建脚本在已校验上游下载器中补齐精确的 `flow.google.com/asb/<mediaId>` 格式，协议必须 HTTPS、无内嵌账号、标准端口且媒体 ID 匹配。保持原下载跟踪／归档和原件不改。更新为当前扩展后仅对有生成响应归属证据、原先 ASB 域名误拦截的记录重开一次下载恢复，不重置任意失败或重新生成。

0.4.9／扩展 1.1.8：重复连接复用未过期的同项目票据；已完成令牌认证、保存项目与真实页面一致的旧连接可自动解除未领取票据留下的等待状态，不重写凭据、不触发连接抖动。显式重配或正在落盘的已领取票据仍受保护。页面响应与控件就绪分开：提示词框及模型设置控件需可用并稳定1.5秒，页面至少完成2秒稳定过程；操作前最多等待45秒。提交前窗口／加载失败限3次退避恢复，只重试参数准备，不重发生成；首次积分读取失败只在控件恢复后有限重试，不周期性打开账号菜单。旧 No-current-window 的纯提交前环境暂停可在同项目真正就绪后自动恢复，其他模型、登录及已提交记录不变。

提交后不再自动刷新：缺媒体编号只做最多3次间隔15秒的只读快照核对，旧恢复计划亦不再发送刷新；主程序与扩展均拒绝旧的自动刷新命令。结果未确认、仍可能生成的任务禁止扩展重载；仅已确认云端结束的下载恢复允许空闲代码更新。1.1.7 的设置入口可在主程序授权空闲更新后自动加载新扩展，不需要复制配对信息。

开项目优先复用同项目页，不重写连接配置；相同配置写入不触发重连。桥接模式禁用上游全局 Object.prototype 与 Webpack 模块遍历／执行钩子，只保留实际使用的网络响应及 DOM 流程，并关闭高频调试日志。原上游文件不改。

`page_recovery.py`：媒体绑定解析失败后仅对原批次进行有限只读快照核对，不刷新页面、不重新生成，不影响其他浏览器。仍无归属编号时保留待核对，不用其他视频替代。失败的原生成响应由主程序私有存储写入独立诊断 SQLite，最多50条、单条截断；热队列只保存摘要。成功响应仅作限量临时缓存，不持续增加密盘文件。诊断不进入外部视频目录，不上传、不输出到明文日志。

浏览器端复用固定版本 FlowCue，仅以构建脚本添加明确接入点。原件不修改；没有把上游桌面程序嵌入主程序。新增桥接认证不进入页面主世界，浏览器凭配对码和固定扩展来源连接。

使用说明：`docs/Flow视频助手.md`。

扩展更新使用 Chrome 官方 `runtime.reload()`，内容脚本只传消息，不能直接调用后台专属接口；启动顺序和权限边界参照 [runtime 文档](https://developer.chrome.com/docs/extensions/reference/api/runtime#method-reload) 与 [内容脚本能力说明](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)。

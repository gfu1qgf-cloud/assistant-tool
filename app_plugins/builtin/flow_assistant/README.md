**0.6.26：图片上传失败上限（历史说明）。**

同一张参考图按SHA-256统一累计上传失败轮次。主程序只在进入上传阶段后收到上传未确认结果，或该上传轮次满3分钟仍未确认时记一次；重复核对旧素材、同一轮重复通知、UI锁申请失败和明确未拖放的错误不增加次数。一次确认成功结束失败连续计数。第1次失败也计入总共5次，不是额外重试5次。

达到5次后，一次性将队列中所有使用同一图片且尚未提交生成的任务标记为“图片已放弃 · 同图任务已跳过”，详情明确显示“图片实际上传失败已达5次，已放弃该图片；所有同图未提交任务已跳过，其他图片继续。”正在准备／上传的同图操作会取消并保留短暂退出占位，之后释放账号与并行名额；已付费、生成中、下载及归档任务保留。健康账号可继续处理其他图片，不因图片失败被禁用。

失败计数保存在现有私有队列设置中，跨浏览器、普通重试及程序重启继续累计；达到上限后，三分钟重传和自动强重试不会恢复该图片，也不会让同图任务逐个再试。若确认要重新测试同一图片，可使用现有“完全重置并重新调度”；手动重置产生新的参考图修订后重新统计，换图产生新哈希也独立统计。失败提示不推断Google没有明确给出的违规原因。

本次只改主程序，扩展源文件、构建脚本、活动扩展和1.1.58版本均未改。使用合成队列和浏览器回执验证，没有操作当前浏览器、鼠标或真实任务数据。源码安装后下次正常重启主程序生效；真实Flow效果仍需更新后验证。

**0.6.20：窗口预算和安全回收（历史说明）。**

浏览器按实际窗口占用限额：通常保留并行数对应的窗口，等待／恢复时最多两倍且总数不超过8。4路并行通常4个，最多8个；连接中断、启动超时仍计入窗口预算，只有明确未启动或收到安全关闭／零窗口回执才释放。达到上限停止补开并显示原因，既有超额窗口逐步回收，不强杀个人Chrome。

多余且可用的空闲窗口会收回，但优先保留足够的正常账号填满并行；异常窗口暂时不能关闭时，不回收仅有的可用补位账号。手动Chrome操作和仅被动读取积分的浏览器不受自动回收控制。设置中的暂时故障恢复开关仍可关闭，说明改为悬停提示。

**统一浏览器管理：** 插件菜单 → Chrome 与 Flow 助手。窗口左侧仅有“Chrome”和“FLOW 插件”两个入口：Chrome显示原配置、分组、外语环境和书签；FLOW插件显示原生成队列、提交、时长分档和连接设置。FLOW状态区仅在FLOW页显示；切换保留草稿、筛选、选中项和浏览器迭代位置。主界面“浏览器配置／分组”“Flow视频生成”、任务右键和查看原任务会自动定位正确的侧边页面。程序设置 → 插件设置 → Chrome 与 Flow 助手 → Chrome启动与快捷键，管理原全局快捷键及默认开启的“启动下一个时，跳过Flow已确认不足10积分的账号”。快捷键、主界面按钮、分组和选中项迭代使用同一个规则，每次点击捕获一次积分快照，按原顺序最多扫描一轮；全不足时只显示原因，不开窗，不反复循环。仅使用已确认且仍有效的低积分／冷却记录；未知、余额过期、已到每日刷新时间或当前登录账号已改变时允许重新检测。手动“启动选中”保留指定打开能力；关闭跳过选项可恢复原迭代行为。

**关闭时保护其他标签页：** 运行时手动关闭、批量关闭低积分账号以及空闲自动关闭都先检查本配置的全部标签页；只要有非本项目标签页（其他网站、其他项目、设置页、新标签页或无法确认地址的页面），就保留整个浏览器并显示具体原因。检查期间新开的标签页也会在真正关闭前再次发现。仅本配置保存的Flow项目及其视频编辑页、且无在途操作、生成、下载或未决结果时才可关闭。此保护不能关闭；旧扩展未加载保护功能时不会发送关闭命令，需空闲后加载桥接扩展1.1.39。关闭成功后暂停该配置，仍可通过“修正后恢复选中浏览器”恢复；拒绝关闭会撤销本次临时暂停，其他账号继续执行。

**自动关闭与故障重开（默认开启，可关闭）：** 在同一“浏览器操作”设置页可分别关闭“积分低于10，空闲后自动关闭浏览器”和“偶发页面故障，空闲后关闭并重新排队一次”。真实／有效余额低于10时，原生成、下载、待核对结果和其他网页操作先结束，再按现有原配置关闭流程核对全部窗口与下载。低积分保留积分冷却，刷新／冷却结束后再检测；页面超时、No current window等偶发错误仅在确认空闲并收到全部窗口关闭回执后冷却60秒，按原提交顺序重新加入候选队列，有任务时最多自动重开一次。重复故障、登录、验证码、网站限制及用户手动暂停保留具体原因，不反复开关。关闭失败有界重试；未收到关闭确认不能当作已退出而重复启动。

**前台 UI 互斥（默认关闭）：** 程序设置 → 插件设置 → Chrome 与 Flow 助手 → 浏览器操作 →“前台 UI 操作互斥”。开启后由主程序维护跨账号的先到先得操作队列，取得权限的浏览器精确切到前台；覆盖FLOW开窗、积分读取、参数设置、图片上传／挂载、提示词填写与点击生成，以及手动激活／F5。提交段结束立即交接，等待云端视频、下载和只读状态查询不占锁。等待其他窗口不计为本次页面操作超时；异常、断线、过期或关闭选项会释放／撤销权限；任务重置／删除会撤销尚未开始的操作，已开始的短UI操作按原回执、释放或期限结束，避免提前交接打断传图。持锁时控件重查最多间隔0.1秒，提示词和提交反馈已就绪就提前继续；保留真实上传、参数及首帧校验。可随时取消勾选并保存恢复原模式；此选项包含前台激活，即使单独激活选项关闭也会激活。需相关配置加载桥接扩展1.1.38；旧扩展会明确显示待更新，不会悄悄绕过互斥。Windows拒绝激活仍显示实际结果，不能保证网站成功率。

**粘贴视频页面链接恢复下载：** 在全局队列选中下载失败／已暂存的任务，右键“粘贴视频页面链接，恢复原视频下载…”。在原Flow项目打开该视频，粘贴浏览器地址栏的 `https://flow.google.com/project/项目编号/edit/视频编号`，无需寻找隐藏的视频文件直链。程序核对原项目和生成回执中的媒体编号，只恢复原视频下载；错误项目、其他视频或缺少原归属证据会说明原因。普通下载重试也优先读取同项目同媒体的新地址，找不到时使用原媒体编号的官方重定向下载地址，不反复使用旧签名；现有下载仍按原Chrome下载编号去重。下载失败仍按上限跳过，不占后续调度，不重新生成。兼容此前手动粘贴原视频HTTPS直链的入口。网站登录、访问权限、视频可用性仍须正常。

**旧版本启动拒绝自动复查：** 正常启动时，仅重新检查过去因主程序支持上限过低、而当前已支持的桥接扩展版本拒绝记录；仍须经过当前真实安装检查。保留手动暂停、积分冷却、账号限制及真实扩展故障；不修改队列、原图归属或千分账号权限。排队提示会显示备用配置启动检查失败的数量和具体原因，避免仅显示“其他图片独占”。

**其他图片独占不占补位名额：** 账号继续只处理原参考图；当前队首需要其他图片时，该账号的页面恢复、积分检测及已连接的旧启动占位都不计作本图可用名额。优先使用能接当前图片的已打开账号，不足时按原有启动间隔补充备用配置，只补空闲并行名额。原任务、原图独占关系、严格提交顺序、高积分权限及积分冷却保持有效。浏览器表将这类空闲账号显示为“其他图片独占”，不再计入当前队首的“可接单”数量；排队说明改为继续寻找其他账号。

**本次失败释放与图片识别修复：** 已审计确认发生在点击生成之前的设置失败，转为失败并释放原账号、并行名额，撤销未使用的本地预留后重新读取真实积分；未知付费结果仍保护原账号，但不占其他账号的启动名额。积分检测完成后以及上传／首帧挂载前自动关闭并确认账号面板消失，关闭失败不盲目拖拽。

**上传等待与截图备用校验：** 普通识别仍使用本次独立文件名及唯一素材编号，补读卡片属性中被通用标题遮住的独立文件名；占位编号不算上传完成。默认无进展等待60秒、仍有上传活动或进度变化最多等180秒，可在“时间与重试 → 扩展与页面”修改。主程序响应超时自动覆盖整段流程。已经确认上传、只是首帧挂载失败时，保留准确素材编号，仅重试挂载，不重复拖图。同账号、同项目、同图连续片段复用原素材；批量完全重置使用同图统一的最新修订，旧队列的逐条修订也统一读取，避免每段误触发重新上传。

**截图备用开关：** 程序设置 → 插件设置 → Chrome 与 Flow 助手 → 浏览器操作 →“图片上传识别失败时，使用截图比对备用校验”。默认开启，仅在普通检索未确认后对当前配置的准确项目页做有界截图对比；截图只在扩展内存中比较，不保存、不发送外部服务。只接受明确图片类型、有效素材编号、可见且无遮挡的缩略图；排除视频组件、视频类型、播放按钮、时长标签和视频海报。原有素材不作为新上传结果；同图多项、近似项或空白占位无法唯一确认时不放行。截图匹配成功后仍要核对唯一素材编号及真实首帧。截图失败沿用普通校验和有限重试，最多三次截图，不另开浏览器、不提交生成。需要主程序正常重启并让相关 Chrome 项目加载桥接扩展1.1.37；不要在运行中的生成页面热更新扩展。旧页面的“Extension context invalidated”表示扩展上下文已失效，须让该空闲页面正常刷新并重新连接，不能当成图片未上传反复拖放。

**临时故障自动重试与明确诊断：** 浏览器表的“等待原因／下一步”保留具体错误，并说明正在自动重试、等待什么，或需要手动处理什么。未连接的配置也显示保存的故障，不再统一显示“待连接”。原生窗口暂时不存在、未提交阶段浏览器响应超时和控件暂未就绪，允许按需重新连接原配置，连接后重新核对；页面仍未就绪时自动刷新原项目并有界重试。原网页忙碌标记、请求或原生操作长期不结束时，停止占用恢复等待并写明原因和检查步骤，其他账号继续接单。登录、网站验证、用户手动隔离及未确认的付费结果保持保护。旧版曾把已核对安装路径的扩展预检记录错误保存为不可重试，升级后重新给它一次预检机会；实际被禁用、版本不匹配等错误显示具体检测结果和修复入口。“可接单”同时核对当前队首的积分需求，剩10或11分不会再声称可接15分的10秒任务。

**立即填充并行名额：** 点击开始／提交任务后立即唤醒派发，不等待调度检查间隔。一次按提交顺序填充空闲名额，各账号独立进行首次核对、上传和生成；连接／积分／结果状态更新后立即补位。同一账号正在执行或上传重试只占自己的名额，不阻止其他名额准备账号。原页恢复、积分检测和新浏览器启动按实际空闲名额并行安排，最多准备需要的账号数量；已有可用普通账号优先派发，不额外检测其他备用账号。新窗口实际启动仍由原来的 3～5 秒间隔控制。未提交参数准备的退避只约束原浏览器，队首任务可转给其他可用账号；后续任务不越过队首。账号隔离、低积分冷却、高积分权限、批次预算和已有付费结果保护仍然生效。

**生成失败与下载跳过：** 仅检查本次绑定媒体的可见卡片，支持繁体“無法生成這部影片”，并联合失败状态与具有明确功能名称的重试按钮识别；圆形箭头或重试按钮单独出现不重新生成。确认失败后沿用原有次数、等待、真实积分复查和媒体归属检查。下载核对／重试达到上限即转为下载已暂存，跳过本条，不保留账号或图片的调度占用；原批次、扣费记录、媒体绑定和准确的迟到结果仍保留，可手动下载或仅重试原结果。扩展只结束匹配原批次的本地等待，不取消云端生成、不关闭浏览器。

**千分账号与浏览器恢复：** 弹窗“是”与右键允许使用统一保存为持久权限，普通账号状态或消费轮次变化不撤销授权。保存实际点击时间，避免工作线程处理延迟把及时点击当作超时。普通账号余额未确认或原页面仍在恢复时不据此认定已用完、反复询问千分账号。已允许的账号仍优先让真实可接单的普通账号执行。明确的未提交页面／参数核对故障按现有连接恢复次数与间隔执行有限 F5，收到新页面就绪证据后重新完整核对参数；达到上限跳过故障账号。登录、封禁、人工暂停与在途付费结果不被自动清除或刷新。

**页面积分刷新时间：** 检测积分时，同时读取账号面板中的“点数每天 HH:mm 刷新”，按该浏览器时区记录下次时刻。积分栏显示页面时间和时区；旧余额到时失效，低积分冷却优先等到页面给出的刷新时刻。到点对已连接且空闲的账号重新检测，不预先增加余额，不刷新网页、不集中打开离线配置。在途任务结束后再检测；失败沿用积分读取次数与间隔设置，识别不到时沿用原缓存和冷却规则。

**千分账号直接授权：** 浏览器表右键 → 千分账号使用权限，可直接允许使用、禁止使用，或恢复自动询问。选择立即保存，重启仍有效；显式允许后仍优先普通账号，禁止不取消已提交任务的核对和下载。

**批量清理浏览器：** 在“浏览器与时长分档”页点击“关闭所有积分不足浏览器”，一次处理所有已连接且确认低于10分的配置。未知／过期余额、未连接配置不处理；生成、下载、待核对及旧扩展会跳过并说明原因。底部显示实际关闭进度与跳过／失败数量，不需逐行检查；关闭后的配置仍可用“修正后恢复选中浏览器”恢复。

**等待与并行：** 已选账号是优先级，不再硬占执行名额。只有能承担当前队首任务的已选账号才优先续用；它在读积分、等待页面／上传／参数重试，或余额只够后面的较短片段时，其他已打开且符合当前任务的账号可使用空闲并行名额。实际在途任务仍受并行上限约束，保留严格提交顺序、同账号单图和高积分授权。谨慎开新浏览器的策略不变，不因等待而额外打开整组配置。

**现有账号先恢复：** 普通积分读取失败先按“积分读取尝试上限／首次积分读取失败重试间隔”核对原账号；仍失败时可对空闲原页安全 F5 一次，再有界核对。页面恢复沿用连接修复上限及等待，原网页不明操作沿用启动占位时限。正常生成、下载、上传重试继续等原任务完成；未知付费结果不刷新、不重复提交。达到上限的账号显示红色及具体原因，允许核对其他账号；手动检测、手动安全 F5、修正后恢复或成功接单可重新进入正常恢复。新启动尚未连接的配置在启动占位期内阻止继续排开窗请求，首个启动仍立即执行。

**顺序与运行时操作：** 队首等待时长、余额、预算或重试倒计时，后面的任务不插队；不同图片与历史优先级不改变派发顺序，完成／下载先后仍取决于网站。浏览器表右键“运行时操作”提供激活窗口、F5 刷新原项目、检测积分、读取页面状态；所有选中项均已连接时才启用。F5 再核对无在途生成、下载及未决结果；重复上传异常及连接恢复可有界尝试原页 F5，不重启 Chrome 进程。前台路径由扩展先请求准确窗口聚焦，再把 Chrome 窗口 ID 交给主程序匹配唯一 HWND／PID 并验证前台，失败如实显示。整行及分档控件：异常红、耗尽黄、高积分蓝、正常使用绿，优先显示异常。

**上传重试恢复：** 新上传前及首帧挂载前清理残留面板，失败后关闭残留面板；准确素材查找覆盖现有素材组件，并在选择器内部滚动查找虚拟列表。仍须匹配唯一准确素材编号及首帧，不猜测旧图片。上传重试会在原文档检查并补装缺失的参考图控制脚本，连接现有页面助手，不刷新、不新建页面、不重放生成。主程序与相关浏览器下次正常重启加载本次源码。

**完全重置入口：全局生成队列顶部“完全重置并重新调度”，或选中任务右键同名菜单，支持多选。** 准备／上传阶段可以解除原浏览器及执行编号绑定，清除该任务重试状态后重新选择可用账号；选中项自动放行，其他暂停项保持原状。可能已经提交或扣费的任务先提示再次扣费风险，经确认后保留原执行快照及费用记录，换新编号重新生成；已有视频保留，新结果分配新文件名。正在保存文件的记录暂不重置，状态在确认期间变化时要求重新按当前状态操作。旧回执不能推进新执行。账号隔离、低积分冷却、批次预算和安全暂停继续有效。

**自动恢复：** 没有扣费或生成证据的准备／上传任务，不再永久等待最初的浏览器编号。等待中的任务允许修复它自己的空闲页面；原页面修复请求先有界等待。连接仍未恢复时默认等 60 秒，再解除绑定重新调度，最多自动换调度 3 次；已提交或结果不明的任务不自动换账号重新生成。旧页面操作在结束或达到正常等待时间前暂不复用同一配置／账号，其他可用账号继续接单。原操作结束凭据可以提前解除等待，等待标记在重启后仍保留。

**参考图串用修复：** 每次执行将原始图片按已保存 SHA-256 核对并复制为独立上传文件，原图和输出文件名保留。托管上传不再凭同名旧图、上传登记或图块数量判定成功；只接受本次独立副本对应的唯一素材编号，并实际挂载到首帧。导入、重新挂载以及最后点击生成前均按准确素材编号核对，旧结束帧会移除，图片不明确就停止生成。托管模式不再走模糊文件名、第一张素材或“输入区有任意图片”的放行路径，同一页面的准备、图片操作和提交互斥。严格凭据需要桥接扩展 1.1.22；旧扩展可继续接收原结果，不能凭旧的上传成功回执发起新生成。

**账号独占图片，同图允许并行：** 同一参考图按内容 SHA-256 识别，可以由多个不同账号按设置的并行数同时执行。每个账号仍一次只执行一条，在该图尚有本次已放行、预算允许的排队任务或生成／下载任务时继续绑定该图，完成该图剩余任务后才接其他图；该账号确实付不起剩余变体或参数不支持时可交给适合的任务。不同目录但内容相同的图视为同一图；同名但内容不同的图彼此隔离。每次上传仍使用独立执行编号和准确图片凭据。

**先用完已选账号：** 并发为 4 时优先保留这批有积分且可用的账号，不因新出现更小余额账号而每做一两条就换人。当前图片完成后，同一批有积分账号继续接下一张图片；低于 10 分、无法承担后续费用、受限或恢复失败时再补账号。单纯等待该图片最后一个结果时，不额外启用第五个账号顶替。余额用尽的账号会退出本批优先名单，之后补回积分也不会抢走仍在工作的账号。同一余额档内先用完已选账号；小额账号优先，千分账号受限时确认保护。

**小额账号优先与千分账号确认：** 低于 100 分的账号先用；正好 100 分也保护为高积分档。账号曾检测到至少 100 分，就按邮箱持久标记为“千分账号”，本地扣算降到 100 以下、浏览器重连、手动检测和程序重启均不清除标记。同一账号的其他浏览器共享标记。旧余额缓存中已有 100 分以上的账号也在下次调度时归入此档。尚有能承担任务的小额账号（包括正在执行的小额账号）时，不为填满并行名额而启用千分账号；未检测配置按配置顺序有界启动／检测，失败、封禁、冷却、参数不支持或余额不足的账号不强行启用。

### 被其他窗口完全遮挡时的运行（0.4.28／扩展 1.1.23）

Windows Chrome 会把完全遮挡的窗口当成后台，可能停止渲染并降低脚本执行频率。此前仅恢复最小化窗口，未处理遮挡；现在主程序打开 Flow 首页、项目或配对入口，以及 Chrome 启动器预设包含 Flow 页面时，增加 Chrome 原生后台运行参数，保持遮挡窗口的渲染、计时和进程优先级。普通非 Flow 启动保持原参数。

这些参数只在 Chrome 主进程首次启动时生效，同一用户数据目录的多个 Profile 通常共用主进程。首次升级后，请等所有生成和下载结束，再正常完整退出 Chrome，并从程序重新打开 Flow；仅刷新页面、重载扩展或只关闭一个 Profile 窗口不能补齐已运行主进程的参数。程序不会自动结束浏览器进程或重开付费任务。正常使用允许窗口被其他窗口盖住，不要求逐个置前。休眠、断网、锁屏和切到其他标签不属于同一运行保证。

成品地址早于对应生成编号到达时，扩展现在缓存有限的准确视频回执，编号确认后自动重新匹配；只读快照也会复核缓存，不依赖视频元素重新渲染。只接受原生成响应的任务、提交和媒体编号，不从旧视频、模糊文件名或单纯地址发现建立归属。

下载前界面改为“视频结果核对 n/上限”，区分尚未取得本次视频编号和已有编号但就绪地址未到，不再把这一步显示为下载重试 0/5。已有只读请求未结束时不重复消耗核对次数。核对上限位于“程序设置 → 插件设置 → Flow 视频助手 · 时间与重试 → 下载结果只读核对上限”，默认 10 次；达到上限后暂存并跳过下载，不占后续调度；仍保存准确迟到结果，供手动下载或仅重试原下载，不自动重新生成。

参考：[Chromium 窗口遮挡说明](https://chromium.googlesource.com/chromium/src/+/main/docs/windows_native_window_occlusion_tracking.md)、[Chrome 官方工具启动参数](https://github.com/GoogleChrome/chrome-launcher/blob/main/docs/chrome-flags-for-tools.md#task-throttling)。本次离线检查不使用真实账号生成；无法据此保证所有线上等待都由遮挡造成。

### Windows 激活、账号续用与立即重试（0.4.43／扩展 1.1.30）

- 0.4.42 只请求 Chrome 激活，不能证明 Windows 前台已经切换。新版本在准确项目的活动标签标题中临时写入一次性标识，主程序验证该标识对应的唯一可见 Chrome 窗口、窗口类名和 chrome.exe，再调用 ShowWindowAsync（仅最小化时）、BringWindowToTop、SetForegroundWindow，以 GetForegroundWindow 是否为同一 HWND 判定结果。多个配置共用进程时不按 PID 猜窗口。
- 标识由主程序签发并绑定当前请求、连接和操作；不能重复消费，原请求已结束、开关关闭或窗口不唯一时不激活。标题清理绑定原 documentId，并且仅在标题仍等于本次标识时还原；原页面也有 2.5 秒自恢复。查找标题最多 5 次，每次异步间隔 100ms；扩展等待 Windows 回复最多 2 秒，失败不重新生成或无限阻塞。

- 后台限速参数用于降低节流，不会赋予页面前台焦点；Chrome 已运行时新增进程启动参数需正常退出后重启才可能生效。Windows 同时只有一个前台窗口，多账号云端生成仍可并行。本次以隔离 Qt、模拟 Windows API 和浏览器消息验证，未在运行中的真实账号上进行激活／付费生成试验。

Windows 接口说明：https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow 。前台切换受系统规则限制，不能用一次调用的返回替代实际前台句柄确认。

# Flow 视频助手

当前主插件 **0.4.29**、桥接扩展 **1.1.24**，底座升级为 [FlowCue 1.1.5](https://github.com/dedeyuyu/FlowCue/releases/tag/v1.1.5)。本次调整同图并行、账号图片独占及积分续用，增加浏览器参数快照；严格参考图校验、完全重置与自动恢复继续有效。

**完全重置入口：全局生成队列顶部“完全重置并重新调度”，或选中任务右键同名菜单，支持多选。** 准备／上传阶段可以解除原浏览器及执行编号绑定，清除该任务重试状态后重新选择可用账号；选中项自动放行，其他暂停项保持原状。可能已经提交或扣费的任务先提示再次扣费风险，经确认后保留原执行快照及费用记录，换新编号重新生成；已有视频保留，新结果分配新文件名。正在保存文件的记录暂不重置，状态在确认期间变化时要求重新按当前状态操作。旧回执不能推进新执行。账号隔离、低积分冷却、批次预算和安全暂停继续有效。

**自动恢复：** 没有扣费或生成证据的准备／上传任务，不再永久等待最初的浏览器编号。等待中的任务允许修复它自己的空闲页面；原页面修复请求先有界等待。连接仍未恢复时默认等 60 秒，再解除绑定重新调度，最多自动换调度 3 次；已提交或结果不明的任务不自动换账号重新生成。旧页面操作在结束或达到正常等待时间前暂不复用同一配置／账号，其他可用账号继续接单。原操作结束凭据可以提前解除等待，等待标记在重启后仍保留。

**参考图串用修复：** 每次执行将原始图片按已保存 SHA-256 核对并复制为独立上传文件，原图和输出文件名保留。托管上传不再凭同名旧图、上传登记或图块数量判定成功；只接受本次独立副本对应的唯一素材编号，并实际挂载到首帧。导入、重新挂载以及最后点击生成前均按准确素材编号核对，旧结束帧会移除，图片不明确就停止生成。托管模式不再走模糊文件名、第一张素材或“输入区有任意图片”的放行路径，同一页面的准备、图片操作和提交互斥。严格凭据需要桥接扩展 1.1.22；旧扩展可继续接收原结果，不能凭旧的上传成功回执发起新生成。

**账号独占图片，同图允许并行：** 同一参考图按内容 SHA-256 识别，可以由多个不同账号按设置的并行数同时执行。每个账号仍一次只执行一条，在该图尚有本次已放行、预算允许的排队任务或生成／下载任务时继续绑定该图，完成该图剩余任务后才接其他图；该账号确实付不起剩余变体或参数不支持时可交给适合的任务。不同目录但内容相同的图视为同一图；同名但内容不同的图彼此隔离。每次上传仍使用独立执行编号和准确图片凭据。

**先用完已选账号：** 并发为 4 时优先保留这批有积分且可用的账号，不因新出现更小余额账号而每做一两条就换人。当前图片完成后，同一批有积分账号继续接下一张图片；低于 10 分、无法承担后续费用、受限或恢复失败时再补账号。单纯等待该图片最后一个结果时，不额外启用第五个账号顶替。余额用尽的账号会退出本批优先名单，之后补回积分也不会抢走仍在工作的账号。首次选入或补位仍按小余额、未检测按 50、千分账号靠后的顺序。

账号图片归属和已选名单随私有队列持久保存，升级兼容旧格式。完全重置会在同一事务里解除选中任务原账号的归属并清除它的参数快照，原在途操作的隔离等待继续有效。暂未放行或预算耗尽的旧排队项不会锁住明确放行的其他图片；控件短暂重绘或等待余额刷新时保留原账号的恢复名额。封禁、积分冷却、账号互斥和原视频归属校验不变。

**小余额优先：** 新选或补位账号按不足 100、100～999、1000 及以上排序；离线备用浏览器也按有效的已知余额启动。高余额账号已在线时，先对已知有足够积分的小余额配置进行有限启动／核对，等待时间采用“浏览器启动占位时间”，超时才使用高余额备用账号。已确认封禁、验证隔离、积分冷却及已有任务的账号不被强行启用。准确原项目报告空闲后，每次连接最多恢复一次明确发生在提交前的准备超时标记。

未检测的账号仅在调度排序中按 50 积分处理，先启动／检测，再决定是否使用高余额备用账号。界面明确标注“未知（调度按 50 分排序）”；不会把 50 写成已检测余额，也不能用这个假设授权上传后的付费提交。检测失败有界等待，已隔离或正在低积分冷却的账号不因假设 50 而重新启用。

“程序设置 → 插件设置 → Flow 视频助手 · 时间与重试”现在共 **78 项**，新增提交前重新调度等待／次数，以及扩展等待主程序握手／心跳无响应超时。后台连接停在建立中、缺少握手或看似在线但没有回应时自动重连，保持浏览器标识、原提交和下载记录，不导航页面；默认握手 15 秒、心跳无回应 90 秒。余额有效期及低于 10 的冷却仍各为 6 小时。

FlowCue 1.1.5 调整手动／托管模式：没有托管连接时减少读取浏览器身份、邮箱、积分和标题，记住本地连接端点；确认连接后才更新标题徽标。仍有轻量连接探测，不把它称为零后台。桥接托管模式沿用本程序的自动调度，跳过旧账号通道的定时徽标及端点存储。原窗口复用、缺失脚本补装、媒体生成回执归属和手动提示词提交红色标记继续保留。

主程序下次正常重启采用本次源码；桥接扩展在浏览器空闲时加载 1.1.24 后采用新的参考图、连接与参数快照校验，既有配对及项目地址保留。


手动提示词收到提交成功回执后，编辑框显示红色背景和边框，表示这条内容已提交到队列。修改文字后立即恢复默认颜色，撤销回原文也保持清除，直到再次提交成功；只调整时长、数量等参数时保留标记。状态按任务和图片随草稿保存，提交并切到下一张时各自独立；失败或过期回执不标红。

已连接的配置由扩展激活原项目标签页和所属窗口；页面未就绪时进入既有的空闲恢复流程，必要时刷新同一个标签页（相当于 F5）。生成、下载、归档或结果未确认时不刷新。同一配置、同一网页入口在“浏览器启动等待”期间合并请求，不影响不同账号独立启动；扩展后台尚未连接时保留原连接入口有限等待，不在每次超时重新生成票据并启动 Chrome。

确需首次打开 Flow 时不再传入 `--new-window`，由 Chrome 复用该配置已有窗口。普通 Chrome 启动器的“启动下个浏览器”仍保留原参数和迭代行为。原窗口复用从主插件 0.4.25 起生效；本次请加载桥接扩展 1.1.22 使用严格参考图校验。

托管任务只接受本次真正创建回执中的唯一输出媒体编号。历史列表的相似字段、提示词匹配、旧视频懒加载、缩略图和未知结果都不能建立或扩大归属；新视频尚未就绪时保持等待，不用旧视频补齐。新旧状态同批返回时按创建 RPC 分开处理。

缺失的扩展脚本会在原项目文档上自动补装；重复恢复不重复注册控制器，不导航、不重提已发送的生成。标签页导航中等待完成，换项目则取消旧请求；原有空闲且无未决任务时的有界刷新作为保底。上述页面恢复由已连接的桥接扩展 1.1.21 执行；扩展后台尚未连接时不以反复打开窗口替代恢复。

明确生成失败后自动恢复：只接受本次 taskId、submissionId 和唯一 mediaId 对应的服务端终态失败，或该媒体卡片明确显示生成失败和退款。默认最多重试 2 次，分别等待 120、300 秒；设置为 0 可关闭。新尝试前重新核对实际账号和积分，不提前把预计退款加回余额。旧批次、失败证据和原积分预留保留；原整批预算仍约束后续尝试。读积分失败有次数上限，低于 10 的冷却不被自动解除；已暂停队列不会被此功能放行。结果未知、单纯超时、历史失败卡片及验证/政策错误不会自动付费重生成。

参数入口仍在主程序：**程序设置 → 插件设置 → Flow 视频助手 · 时间与重试**。新增“明确生成失败后自动重试上限”“生成失败各次重试等待”“生成重试前积分重查间隔”，合计 72 项，通过主设置窗口“确定”统一保存。

此前主插件 0.4.23／扩展 1.1.20：入口“程序设置 → 插件设置 → Flow 视频助手 · 时间与重试”，通过主程序的 `PluginSettingsPage` 接口加载。69 项时间和重试参数按积分与关闭、连接与启动、超时与重试、扩展与页面、配对向导分组，可搜索和恢复默认，由主设置窗口的“确定”统一保存到程序配置；取消不应用。原私有设置作为首次兼容默认值，Flow 任务窗口不再重复维护时间参数。正余额默认有效 6 小时，0 表示不过期；低于 10 的冷却仍独立默认 6 小时。页面未响应默认 180 秒，可另设。保存后后台采用，并同步到已连接的新版扩展；旧扩展保留兼容等待，加载 1.1.20 后完整生效。

最近一次真实检测余额及本地扣算结果按账号／准确项目持久保存，重连、重启、页面失联或检测失败不再直接删掉数字。过期显示旧值并在空闲有队列时重新检测；无法确认当前账号时停止派发，付费准备和提交仍核对实际账号。失败数据不更新余额或检测时间，断线也不会撤销费用预留。设置写入失败会明确显示未保存，编辑不会丢失。首次安装此修复需正常重启主程序并加载新版扩展，以后可自行调整时间。

主插件 0.4.22／扩展 1.1.19：账号余额低于 10 积分时持久冷却 6 小时，同账号窗口、重连和重启共享。期间不自动打开、检测积分、修复页面或提交新任务；10 积分仍可用于费用不高于余额的任务。冷却到期且有可执行队列时重新检测，手动积分检测／顶部刷新可提前确认；仅成功读到至少 10 积分才提前解除，失败或仍不足 10 保留冷却。普通正余额不增加几分钟的过期轮询。浏览器表显示记录余额、冷却状态和截止时间。

最后一条生成把余额扣到 10 以下后，原任务继续生成、下载和归档。全部任务确认保存后，主程序和扩展再核对网页空闲、全部下载及通知完成，自动关闭该 Chrome 配置的窗口。下载中、归档失败、结果待核对、暂存下载及其他 Flow 页面忙碌时保持打开；其他账号继续并行。手动检测的结果至少显示 30 秒后才考虑关闭。旧版扩展缺少此能力时不尝试关闭；主程序下次正常重启、对应扩展空闲后加载 1.1.19 生效，保留配对和项目。

主插件 0.4.21／扩展 1.1.18：修复浏览器冷启动与二次打开时页面桥接未就绪后长期停在自动确认的问题。启动名额保留到页面和首次积分读取完成；连接长期无响应时，对没有生成、下载或未决结果的准确项目最多自动恢复三次，先检查脚本和按钮，再按需刷新当前项目。扩展的持久提交／下载记录也会阻止误刷忙碌页面。托管页面恢复旧状态不会自动重提旧批次；页面状态加载完成后才允许准备新任务。没有登录／项目访问权限或触发验证时仍显示实际原因，账号隔离必须手动重置。

修复失效 QWebSocket 对象残留、重连报“wrapped C/C++ object ... deleted”及拖停其他账号的问题。修复兼容扩展的历史超时标记无法恢复、准备等待被下一条任务绕过，以及自动时长分档挡住模型默认任务的问题。时长面板关闭／重建后会重新定位并核对实际选中秒数；明确不支持的参数只限制该参数组合，其他时长继续接单。界面显示实际占用并行数／设置上限和未就绪数量。低积分优先及同账号互斥保留。

主插件 0.4.20、扩展 1.1.17：完整审查调度、积分、连接重启、参数准备、生成回执、媒体绑定及下载归档。调度在可用且足以支付费用的账号中先使用不足 100 积分的，再用 100～999 积分的，1000 及以上放最后；手动固定时长、任务优先级、同账号互斥和并行上限仍生效，自动时长分档不再使大余额账号优先。修复错误浏览器消费回执、失败积分检测误用部分数据、迟到回执倒退状态／重复派发、本次未提交准备在重启后误入核对、运行中或归档中被重试／重生成、过期归档结果覆盖新批次、取消任务被迟到状态复活、空媒体编号补齐及缺失快照误判归属。批次去重记录区分已发送、已接收、已拒绝，不再把发送记录当作成功；重连补查丢失的下载完成事件，并记住已确认事件。

账号故障独立持久记录：明确账号停用／封禁、登录失效、需要验证分别标记，超时／普通服务器错误不猜测封号。Flow 明确错误提示和 Google 登录重定向可报告故障；未提交任务可转交其他账号，已有提交证据则保留核对且不退款、不重生成。封禁标记不被重连、普通浏览器恢复或后续登录提示自动清除。浏览器右键新增“标记选中账号不可用”和“重置选中账号状态并重新检测”；仅显式重置选中账号才移除隔离，重新读取积分，保持队列暂停／未决任务状态。同账号多个窗口共享隔离，其他账号仍可继续；网站验证与风险暂停仍需处理后明确继续。

### 被其他窗口完全遮挡时的运行（0.4.28／扩展 1.1.23）

Windows Chrome 会把完全遮挡的窗口当成后台，可能停止渲染并降低脚本执行频率。此前仅恢复最小化窗口，未处理遮挡；现在主程序打开 Flow 首页、项目或配对入口，以及 Chrome 启动器预设包含 Flow 页面时，增加 Chrome 原生后台运行参数，保持遮挡窗口的渲染、计时和进程优先级。普通非 Flow 启动保持原参数。

这些参数只在 Chrome 主进程首次启动时生效，同一用户数据目录的多个 Profile 通常共用主进程。首次升级后，请等所有生成和下载结束，再正常完整退出 Chrome，并从程序重新打开 Flow；仅刷新页面、重载扩展或只关闭一个 Profile 窗口不能补齐已运行主进程的参数。程序不会自动结束浏览器进程或重开付费任务。正常使用允许窗口被其他窗口盖住，不要求逐个置前。休眠、断网、锁屏和切到其他标签不属于同一运行保证。

成品地址早于对应生成编号到达时，扩展现在缓存有限的准确视频回执，编号确认后自动重新匹配；只读快照也会复核缓存，不依赖视频元素重新渲染。只接受原生成响应的任务、提交和媒体编号，不从旧视频、模糊文件名或单纯地址发现建立归属。

下载前界面改为“视频结果核对 n/上限”，区分尚未取得本次视频编号和已有编号但就绪地址未到，不再把这一步显示为下载重试 0/5。已有只读请求未结束时不重复消耗核对次数。核对上限位于“程序设置 → 插件设置 → Flow 视频助手 · 时间与重试 → 下载结果只读核对上限”，默认 10 次；停止主动探测后仍接收迟到结果，准确结果到达时自动恢复原下载，不重置实际下载失败次数，也不自动重新生成。

参考：[Chromium 窗口遮挡说明](https://chromium.googlesource.com/chromium/src/+/main/docs/windows_native_window_occlusion_tracking.md)、[Chrome 官方工具启动参数](https://github.com/GoogleChrome/chrome-launcher/blob/main/docs/chrome-flags-for-tools.md#task-throttling)。本次离线检查不使用真实账号生成；无法据此保证所有线上等待都由遮挡造成。


### 浏览器参数快照（0.4.29／扩展 1.1.24）

同一浏览器首次完整核对成功后保存参数快照。后续相同页面实例、账号、项目、扩展版本及相同模型/时长/比例/分辨率，直接进入独立参考图处理和生成设置，省掉额外的 prepare 核对请求。生成流程本身仍设置并核对实际参数、确认当前账号和准确参考图，随后只提交一次。快照不冒充余额，也不替代单条/批次预算或图片上传回执。

“程序设置 → 插件设置 → Flow 视频助手 · 时间与重试 → 浏览器参数快照有效期”，默认 6 小时，0 关闭；复用不会不断延长原快照时间。页面刷新、重连、换账号/项目/参数/扩展、参数失败或完全重置后需要新的完整核对。只有已知固定费用的参数使用快照；模型默认及没有固定费用的参数继续完整核对。旧扩展缺少页面实例凭据时正常完整核对，载入 1.1.24 后才启用此优化。

首次核对状态改为“首次核对／更新快照”；快照命中时直接显示后续上传和提交进度。主插件为 0.4.29，桥接扩展为 1.1.24，上游仍为 FlowCue 1.1.5。程序和扩展在空闲时正常重新载入后生效，配置、配对和任务数据保留。

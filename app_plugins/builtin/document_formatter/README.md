# 文档自动格式化

入口：插件 → 文档自动格式化。插件管理中可以独立禁用；下次正常重启生效。

默认规则来自用户提供的四张操作截图：A4纵向（21×29.7cm），上下边距1.8cm、左右1.5cm；左右缩进0、首行0.84cm；标题14pt加粗，正文12pt，行距150%。规则可以在窗口修改并保存到主程序管理的插件私有数据目录。原要求没有指定字体名称、对齐方式和段前段后数值，因此默认保留这些设置，包括正文中已有的加粗、斜体、链接与颜色；可明确勾选段前段后归零。

标题优先采用现有Heading/Title或ODT的heading语义。没有标题样式时，默认将首个非空、非结构化段落作为标题，可取消该策略。段落清单中可以逐段选择标题、正文或保留；此选择只决定格式，不重建目录或更改原有标题级别。列表、表格、目录、脚注、批注和图形内的文字默认保留。页眉页脚不参与正文格式化。

## 本地ODT

1. 添加一份或多份ODT，读取/刷新文档，查看段落清单。
2. 点击“按规范另存当前ODT”或“批量另存全部ODT”。批量时，未单独预览的文档自动按同一规则识别；已预览的文档沿用其段落选择。
3. 成品写在原文件旁，名称为“原名-已格式化.odt”；重名时追加序号，不覆盖源文件或旧成品。可直接打开成品或打开文件位置。

只修改content.xml、styles.xml中的格式及样式引用。文字、链接、图片、元数据及其他ZIP条目保留，源文件始终只读。预览后或处理期间源文件变化会拒绝写成品；坏文档逐项列为失败，不阻止其他文件。支持关闭窗口后继续执行与协作取消。密码加密ODT、超过64MB的输入、超过256MB的展开内容、异常XML/ZIP路径和超过1500段的文档会明确拒绝。ODS是表格，不属于此功能。第一版不接收DOCX作为待格式化文件；DOCX仅用来提供规范。

## Google Docs

Google文档使用官方Docs API，不通过浏览器鼠标脚本，也不把本地ODT上传到任何服务。首次使用在Google Cloud项目启用Google Docs API，选择“桌面应用”OAuth客户端JSON，然后从本窗口Google Docs菜单授权。可以选择主程序现有的同一份客户端JSON，但Docs需要单独授权；不会覆盖Google Sheets/Drive令牌或其他API密钥。只申请`https://www.googleapis.com/auth/documents`权限，不申请Drive文件列表或文件管理权限。令牌、客户端副本和恢复记录位于`PluginData/document_formatter/`，通过宿主存储接口管理，VC模式下位于已验证加密卷；没有明文回退。

输入Docs链接并读取，再选择文档分页。文字范围使用API原始UTF-16索引，不能用Python字符长度代替。执行前确认目标名称，GET校验原修订号，保存恢复记录，再以requiredRevisionId提交单个原子batchUpdate。只发送页面、段落和文字样式更新，不删除或重写文本、不改其他分页。页面设置会将所选分页设为分页模式；恢复记录也保留原分页模式及分节边距。

Google Docs菜单可以恢复上次成功格式化的原样式。若后来又有人编辑或上次请求结果不明确，拒绝自动恢复并提示使用Google自身版本历史。请求超时不自动重放；云端可能已经接受操作，应先核对在线状态。若卷失效导致成功请求后的状态保存失败，会明确提示“请求已完成但保存恢复状态失败”，不会误报为未修改。恢复记录不是文档整体内容备份，不用于覆盖后来新增的文字或评论。

离线模式只禁用Google功能，本地ODT正常使用。Google账号必须对目标有编辑权限，公开分享不能代替OAuth；API未启用、权限和网络问题应按错误提示处理。当前Cloud接口仅进行了模拟测试和已安装客户端结构核验，未对用户真实云文档做写入验证。

段落清单为修改预览，不是精确分页渲染。ODT输出已通过内容/样式结构和现有ODF解析器校验；本机捆绑运行时未提供LibreOffice渲染器，未调用用户桌面LibreOffice做自动渲染。

官方参考：[格式化文字](https://developers.google.com/workspace/docs/api/how-tos/format-text)、[Docs API更新请求](https://developers.google.com/workspace/docs/api/reference/rest/v1/documents/request)、[修订控制](https://developers.google.com/workspace/docs/api/reference/rest/v1/documents/batchUpdate)。

# 智能搜音乐

默认使用 `laion/larger_clap_general` 大模型和精细覆盖。首次点击“建立 / 更新索引”在后台生成独立新索引，之后增量处理新增或变化的音乐。精细模式每约 10 秒抽取一段，长曲最多 256 段；均衡模式每约 20 秒、最多 128 段。源音乐不会移动或上传。

窗口和插件设置都可以切换模型、采样覆盖及个人偏好。`CLAP Unfused` 是经过实际推理验证的对照模型，不代表它在每一种情绪上都优于大模型。模型在后台按需加载，不同时常驻多个模型；工作期间的设置变化延后到任务完成再应用。

原 `SmartMusicSearch/index.sqlite3` 保留。选择“大型 CLAP”加“旧版抽样”即可复用旧索引；其他模型和覆盖模式各有独立数据库。切换时索引数量变化不表示旧记录丢失。偏好保存在同目录的 `preferences.sqlite3`，该目录由 Git 忽略。

搜索结果右键可标记“符合本次情绪 / 不符合本次情绪 / 清除本次情绪标记”。只影响相同查询及标签组合，标记跨模型复用；源文件发生变化后旧标记不再应用。显示的音频相似度不包含个人偏好加分。“参考我的喜好”可关闭偏好排序。文件名匹配仍是独立、默认关闭的功能。

检索使用多个描述的平均文本特征，并比较连续区间的平均和低分部分，而非只取一个瞬间最高分。模型加载会检查明显不同的描述是否产生不同特征；自检可以发现向量坍缩，但不能保证细腻情绪判断准确，结果仍需试听。

曾测试 `laion/larger_clap_music`，发现不同文本的特征相似度约 0.999，因此不注册该模型。公开复现：[MTEB #5069](https://github.com/embeddings-benchmark/mteb/issues/5069)。CLaMP 3 的 MERT 配套权重及 MuQ-MuLan 权重有非商业许可限制，本版本未集成。

可选开发验证：`python -m tests.benchmark_smart_music --output <本地报告路径>`。对照程序只读原音乐，在报告旁的独立测试目录保存索引；报告是候选及速度测试，不是人工评定的准确率。

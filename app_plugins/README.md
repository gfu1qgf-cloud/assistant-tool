# 应用插件接口

智能剪辑核对窗口：任务下拉框后“刷新”会重新扫描该任务目录，打开原有片段选择界面；确认后后台重新分析，仅在原窗口替换当前任务的排序、缺段、裁切与核对状态，其他任务的未保存修改保留。选择界面取消不更改旧结果；当前任务旧人工决定会在成功刷新后重置。健康语音识别缓存继续使用，整项分析强制重新核对；同路径替换的源视频重新加载解码器和画幅，不沿用旧的暂停／预加载帧。刷新期间按钮变为“取消刷新”，不能同时保存／导出旧计划；失败或取消恢复旧结果。关闭核对窗口不取消后台分析，完成后可恢复新结果，显式刷新始终再次交给用户核对，不自动导出。原“视图→刷新时间线”仍只应用表格编辑，不重新选择视频。

当前插件接口版本为 `1`。内置插件由主程序显式安装，暂不从任意目录自动执行第三方 Python 文件，避免未知代码在启动时获得业务配置和本地文件权限。

“文档自动格式化”位于插件菜单，支持本地ODT文字文档和Google Docs，不是ODS表格。默认规则和使用方法见[插件说明](builtin/document_formatter/README.md)。本地批量另存到原文件旁，Google仅修改所选分页的格式；标题/正文可在段落清单调整。使用宿主后台任务与统一存储，关闭窗口继续执行；独立Google授权及恢复记录放在加密插件数据目录，不改既有表格／网盘令牌。本次只新增插件，不改变任务登记、统计或视频业务。

## 任务节点工作流 0.5

### 叠加内容的显示时段与出入场（2026-10-14）

节点分类“视频与画面 → 时间控制 → 显示时段 · 出入场”。连接：`添加文字／图片／GIF／视频／字幕 → 显示时段 → 视频解算器的操作输入`；原视频直接接解算器的视频输入。也可把多项叠加操作接入同一显示时段，按原连接次序合成。

开始设 `20`、结束设 `0`，前20秒完全隐藏，20秒开始出场并显示至视频末尾。结束为绝对秒数，代表退场完成时刻，不是持续长度；例如结束30、淡出0.5秒，则29.5秒开始淡出，30秒完全消失。出场／退场独立选择直接切换、淡入淡出、四向滑动并淡入淡出、由小／大缩放并淡入淡出；滑动／缩放幅度可调，滑动使用缓入缓出。开始／结束数字输入连接后覆盖面板设置。时段过短会按比例缩短两端动画并提示，开始超出视频则明确报错，不静默生成缺内容的成品。

“素材播放时钟”默认自动：图片／GIF／视频／滚动文字在出现时从头开始播放，字幕保留输入SRT原时间，不错开人声。需要把从0秒开始的SRT整体延后，可选“出现时从头播放（字幕时间相对开始秒）”；选“跟随整段视频时间”则隐藏期间素材仍往前走。节点不改原SRT、视频、音频、资源池游标或成品长度。再次接一个显示时段会覆盖前一个，不叠加未知时间偏移。此节点控制叠加内容，不用于延时整段背景或压缩／LUT操作。

预览节点接解算器输出，在其“视频预览位置（秒）”或预览窗口中切换到19／20／21秒即可检查，随后刷新；预览与最终导出使用原组件绘制／抠像／混合、字幕ASS和相同FFmpeg过滤器，一次最终编码，不产生完整中间视频。未接此节点的原有图层保持原效果。

出入场种类参考 [Adobe动画预设说明](https://www.adobe.com/learn/after-effects/web/animate-text-presets)，独立实现，不复制其预设资源；时间门控、Alpha淡入淡出与动态缩放按 [FFmpeg官方过滤器文档](https://ffmpeg.org/ffmpeg-filters.html) 并用随程序正式二进制验证。

主菜单“工作流 → 节点工作流…”打开独立窗口，不嵌入主界面、不重新挂接任务表／达芬奇分页／日志及分割线。“工作流 → 节点窗口吸附主窗口”或节点窗口“窗口 → 吸附主窗口”开启跟随；拖近主窗口四边后松手也可吸附，拖离即脱离。跟随按主窗口绝对位置计算，不积累位移误差；主窗口调整大小后重新对齐，屏幕边缘限制位置以防窗口跑到屏幕外（主窗口最大化、旁边空间不足时可能重叠，但不会挤压主布局）。主窗口最小化时暂时隐藏已显示的节点窗口，恢复后重新显示；手动关闭的窗口不会因此重新打开。关闭节点窗口仅隐藏、保留工作流和位置、不取消后台任务；退出主程序仍按原规则等待或取消任务，并询问是否放弃未保存工作流。

任务入口提供独立输出端：任务路径、任务文案、编号、名称、语言、类型、语音 ID、管理员、日期、参考链接、审核要求和统计字段等。完整行快照只在入口内部保存，不作为整个对象传给业务节点。默认连线是：任务路径 → 列出文件（listdir）→ 智能剪辑的视频列表输入；任务文案 → 智能剪辑的文案输入。编号、名称、语言是可选输入；剪辑后的视频和字幕接基础字幕样式节点，最终写入当前任务目录。

listdir 的规则全部可改：是否递归、包含／排除通配符、排除文件名关键词、递归时忽略目录、自然序号／文件名／修改日期排序。默认不进入子目录，排除包含 `-口播`、`-reels`（不区分大小写）的文件名；递归时默认跳过程序结果／缓存目录。规则可清空或重写。智能剪辑只接受传入列表，不会另搜文件、自动补文件或再用隐藏规则筛掉输入；非视频和空列表明确报错。清单有顺序和文件签名，最终处理报告记录实际输入文件。

额外表格列可用“任务自定义字段”节点按原始列名输出一个文本值；不传整包任务。也可使用独立“目录路径”和“文本”节点提供数据，剪辑节点不要求绑定任务对象。多选任务分别提交后台队列，结果列表逐项显示成品、提醒、跳过和失败原因；默认单任务失败不阻止其他任务，可预设遇错停止本批次。排队期间可以取消，隐藏面板不中断执行。打开旧的整包任务工作流时会转换为字段端口与显式 listdir，保留已有文案覆盖连线及递归行为；原 JSON 文件不自动修改。

节点菜单按任务与文件、文本与转换、数值与逻辑、处理与导出、预览、插件处理分组。基础节点包括数值常量、加减乘除／取余／最小最大值、数值比较、布尔与／或／异或／取反、文本与数值转换、文本拼接／替换、文件计数、文件集合并／交／差集、按序号取视频和条件选择。文件集合按路径去重、保持顺序，只接受同一目录／任务，不改原文件。条件选择是严格的数据选择：两侧上游均执行，不代表跳过另一侧耗时任务。任务编号继续保留原文本（如前导零），另提供数值输出；不是完整数值时该输出为空，连接必填数值输入会报错，不伪造零。

“文件 → 新建任务工作流”或“新建文件结算／导出示例”提供明确的两步链：视频与操作 → 视频结算（只编译计划）→ 导出成品。首次打开默认使用独立导出链。最终执行导出才编码一次，不产生完整中间视频；任务模式自动落到任务目录，指定路径模式需填写 MP4 路径，两者都不覆盖原文件或旧成品。旧的“结算并导出（兼容）”节点保留原有行为，可继续使用。

“节点 → 预览 → 预览”添加独立的多态预览节点，连接需要查看的内容，双击或右键“打开预览内容”；也可使用右侧按钮或“运行 → 打开所选预览节点”。普通节点不再提供预览按钮。预览输入、输出按接线自动确定同一具体类型，原样透传，不保存写死的类型。后台只执行该节点和上游，不执行下游导出；绑定多项任务时预览首项，可能包含模型分析耗时。文件列表显示顺序、数量和路径；视频／视频计划显示指定时间的静态画面（不是完整播放），计划预览包含已接入的字幕等处理效果。图片保持比例，最多 720×720，不创建完整临时视频，临时 PNG／字幕文件用后清除。顺序流需先转为可定位内存资源；预览可取消，关闭面板不取消后台执行，不写登记表或推进资源轮换。

条件选择只有一个菜单项：“节点 → 数值与逻辑 → 条件选择”。第 1 路为布尔条件，第 2、3 路数据及输出共享类型组，支持文本、数值、布尔、文件列表、目录及媒体资源等；接线推断类型，类型不一致立即拒绝，导入不匹配的工作流也会阻止执行。两侧上游都会执行，不是惰性分支。旧的分类型条件选择／预览节点保留注册，以兼容已保存的工作流，但不再堆在新建菜单中。

“视图 → 连线样式”可选平滑曲线、直线、直角折线、圆角折线，随本工作流 JSON 保存，旧工作流默认为平滑曲线。Alt + 左键点击连线插入小型多态中间接点，拖动接点整理走线，选中按 Delete 或右键删除自动恢复连接。接点输入输出同类型，保持资源身份、流能力和 Merge 输入顺序，不复制数据或创建媒体文件。若恢复会产生重复连接，明确拒绝删除，不偷偷去重改变操作次数。

中键平移以按下位置的总位移计算，避免长拖和缩放取整累积漂移；滚轮缩放，左键移动节点。连线拖到空白处松手取消，点空白／右键／Esc／失去焦点也可取消；先点输出再点输入的连接方式仍支持。

智能剪辑节点沿用已有模型、气口和字幕设置，也可在节点参数里覆盖。默认保守策略保留严重不确定内容，保留有直接证据的重复朗读裁切；自动策略会排除疑似多余片段；跳过策略遇到内容疑点直接跳过任务。执行中没有人工审核、确认或输入对话框，提醒只在最终结果中呈现。旧交互式智能剪辑的确认逻辑和缓存记录不被节点策略改写。模型选择仍受原有安全切换限制：若当前进程已加载另一模型而无法安全切换，任务明确失败，不自动换低精度模型。

字幕节点必须同时连接视频和字幕，支持已有 SRT 或智能剪辑输出的时间轨；剪辑时间映射和源视频保持关联，避免跨任务误配。剪辑节点输出的是延迟剪辑计划，不是完整中间视频；最后一次 FFmpeg 合并剪辑与字幕，统一规格并在需要时补齐无声段音轨。任务成品 MP4、对齐 SRT 和报告写入任务目录的 `节点工作流结果/`，重跑自动编号，已有文件不覆盖。listdir 在后台执行时枚举并固定文件签名，枚举后至落地前发生变化会拒绝落地；原文件导入节点仍在提交时固定签名。

原文件输入示例和压缩内存／管道示例在“文件”菜单中保留。文件方式导入本地视频和现成 SRT，不加载 AI 模型、不改人声或时长；其中音频保持原编码复制，MP4 不支持的原音频编码会明确报错。尚未接入批量文案视频的全部动态字幕预设，第一阶段每张图只选择一个最终输出结算器。

圆形为必填输入，三角形为可选输入，带“+”的输入可接多个节点。从输出端拖到输入端（或先点输出再点输入）接线。中键拖动平移整个画布（包括在节点上按中键），不会改变节点坐标；滚轮缩放，左键仍移动节点／框选。“视图 → 适应画布”显示全图。右键节点删除/选择输出结算器，右键连线断开/调整 Merge 顺序。只有所选结算器及其上游完整才可执行；缺失必填列表或文案连线、类型不匹配、循环、插件禁用和版本不兼容会阻止执行。

工作流在本面板“文件”菜单另存 JSON，保存节点类型、版本、参数、资源位置和连线，不保存绑定任务、配置密钥、函数、Qt 对象或 OS 文件句柄，不写入全局配置。资源在运行时转换为带大小/修改时间快照的 `ResourceRef`；延迟剪辑使用 `VideoTimeline`，字幕使用 `SubtitleTrack`。临时目录在成品磁盘，取消/失败后清理，源文件和已存在成品不覆盖；报告记录任务归属、模型、裁切区间及疑点，不复制完整任务原文或配置密钥。

插件可选调用 `context.register_node(NodeDefinition(...))`，类型命名空间必须为 `plugin_id.node_name`。公共定义从 `app_plugins.api` 导入 `NodeDefinition / NodePort / NodeParameter`；`DirectoryRef`、`FileList` 等值类型位于 `model.node_workflow.contracts`。`prepare(task, params, services)` 只固定纯配置及资源锁声明，不隐式枚举业务输入；独立文件工作流的 task 为 None。`relative_writes` 可声明输入目录下的缓存等相对写入目录，宿主为本次任务及显式目录节点声明锁；自定义目录源提供者需通过 resources 声明自己的写入锁。不能把控件或密钥放入工作流文件。`build(inputs, params, context)` 在工作线程按连线获取业务数据、响应取消，不查询当前 UI 行或从宿主任务包偷取未连接字段。计划节点用 `execution="plan"`，计算节点用 `"compute"`，均不可弹窗或等待用户。公共端口类型包括 `directory / files / text / boolean / audio / video / subtitles / operations / render_plan`。禁用插件不会提供它的节点，注册失败会回滚登记；旧插件不注册节点仍可正常使用。

### 压缩内存 / 管道媒体试验

多态端口接口为 `NodePort("key", "标题", "any", type_group="value")`；同一个节点里同一 `type_group` 的输入、输出必须推断成一个具体类型。分组仅在该节点内有效，组名相同不会让不相连的节点互相绑定。平台沿全图连线统一类型，重接后重新推断；未知类型不能执行，运行时仍核对实际返回值，不能用 `any` 绕过媒体类型、资源能力或数据验证。固定类型端口不要填写 `type_group`。具体业务节点（数值运算、字幕、文件枚举等）保持必要的固定类型约束。

节点面板“文件 → 新建内存视频示例 / 新建管道视频示例”已接好导入、传输、字幕、Merge 和结算器。点击导入节点指定视频与 SRT，点击结算器指定新成品路径即可测试。传输节点也可在“节点”菜单单独添加；它接受已经生成的压缩视频资源，不直接接受尚未编码的剪辑计划，后者应直接连接最终结算器。

三种存储方式都通过同一种 `ResourceRef` 视频端口传递。`storage` 为 `file / memory / stream`，非文件资源使用本次执行会话的 `resource_id`；它不是可直接打开的文件名。节点必须通过 `context.media.info(ref)`、`context.media.open_reader(ref)` 获取信息或读数据，不把 `BytesIO`、生成器、Qt 对象或进程句柄传到端口上。内存读取器可定位且有独立游标，不为每个下游复制整个视频；管道为可重新打开的顺序流，不能定位。需要定位的端口声明 `NodePort(..., capabilities=("seek",))`，不满足时执行器拒绝连接资源并提示先缓存。第一版只支持可重新打开的流生产者，不假装兼容一次性视频源。

插件可使用 `context.media.register_stream(factory, info, dependencies=())` 注册可信代码提供的压缩 MP4 生产者；`factory(context)` 每次返回新的可读取、可关闭流，`info` 必須包含有效 `duration`、`video.width / height` 和布尔 `audio`，本地依赖使用文件快照。生产结果可以没有中间视频路径。生产者、缓冲区与进程由执行会话持有；工作流 JSON 只保存节点参数与生成配方，不保存临时资源 ID 或回调。完成、失败和取消后释放，不能拿上一任务的内存句柄给新任务使用。

本地视频传输仅重新封装为分片 MP4，不重新编码；保留音频起始补偿，最终字幕仍一次编码。MP4 不支持的流会报错，不静默修改编码。内存节点默认压缩缓存上限 128 MiB，可调 16–512 MiB；所有同时运行的节点工作流压缩缓存总上限 512 MiB。该预算不包括 FFmpeg 解码帧、编码器和系统管道缓冲。超限提示改用管道，不偷偷落盘。纯管道采用有界缓冲和反压；内存→管道→内存复用已有缓存。源视频变化、跨会话引用或释放后的资源会明确报错。

这仍是媒体传输原型，没有把智能剪辑全部分析/导出或其他插件迁移为内存执行。最终成品会保存到用户指定的目录；“无中间视频”不意味着不保存成品、小型字幕附件或日志。内存资源在程序退出后不保留，保存工作流后可再次生成。真实合成媒体测试入口为 `tests/test_node_media_smoke.py`，需要设置 `NODE_FFMPEG`；纯契约与内存限制测试为 `tests/test_node_media.py`。

## 插件启停

入口为“插件 → 插件管理”。列表显示名称、版本、本次启用状态和下次启动开关，支持名称/ID搜索、多选及右键批量启停。取消勾选“垃圾分类每日提醒”并保存，重启后不再出现垃圾提醒、官方公告检查或其主界面卡片；发给组员时可一并关闭其他个人用途插件。

主配置 `plugin_enabled` 按稳定插件 ID 保存布尔值，例如 `{"waste_reminder": false}`。缺项保持启用，兼容旧配置。此处只控制本程序的插件功能，不是代码沙箱：内置模块仍可能被导入，插件注册会保留功能描述；禁用插件不执行启动、应用设置及运行配置回写，不创建普通面板/设置页，不提供命令，也不接受其后台任务。主程序少数历史控件别名仍保留隐藏且不可操作的控件，用于兼容原有配置读写。禁用不会删除插件目录、密钥、清单、历史或资源。

新的公开示例配置默认关闭 Valle Lomellina 垃圾提醒，避免未设置所在地的组员收到个人提醒；已有本机配置不自动改动。分享自己的配置时，仍应在列表中明确选择适合组员的插件，同时去除密钥和私人业务数据。

开关保存后必须重启才生效；本次状态与下次设置分开显示，避免将未停止的后台任务误标成已关闭。修改任一插件开关不会热卸载模型、播放器或 QThread。已禁用插件的配置在其他设置保存时原样保留，再启用可继续使用。第三方未知插件不能因为“禁用”就被当成安全代码。

## 做饭小助手

“做饭小助手”从“插件 → 做饭小助手…”打开，包含食材库存和中文做饭方案。默认 1 人做 2 顿，调料仅默认勾选盐。配置页为“程序设置 → 做饭小助手”，独立配置键 `cooking_assistant`，默认模型为已核对官方文档的 `gemini-3.8-flash`，可改模型名；不影响其他功能的模型选择。菜谱使用主程序共享 Gemini Key，后台生成且反馈密钥状态，不加载本地模型或新增依赖。

库存、界面偏好、最近方案与最多 30 份缓存保存在 Git 忽略的 `CookingAssistant/food.sqlite3`。同批食材同一天复用缓存，点“换一组”才重新联网。生成菜谱不扣库存，用户通过“用掉／减量”确认使用量；同一种食材可分批登记。自己设置的检查日与包装 use-by / best before 分开标注，待核查、超过日期或变质条目不自动推荐；程序运行时对临期/待处理食材每日提醒。日期提醒不能判断实际新鲜度，不要擅自延长包装食用截止日。

菜谱为 AI 生成而非复制菜谱网站。库存管理离线可用；只有用户生成时发送所选食材、调料、人数及偏好。剩菜、米饭与日期标签的固定安全说明附官方 FSA/GOV.UK 链接（2026-10-01 核对），不依赖模型自由生成。程序关闭时不销毁仍在工作的 QThread，窗口关闭仅隐藏并保留状态。

## 共享 Gemini 密钥

主程序持有 Gemini Key，管理入口为“程序设置 → AI 密钥”，也可从“工具 → AI 密钥管理 · Gemini…”打开。旧配置的 `gemini_api_keys` 原样兼容；插件不能再维护或回写一份 Key 副本。可用状态保存在主配置的 `gemini_api_key_statuses`，以 Key 指纹索引，不保存原始错误响应。

插件可在后台线程使用 `context.gemini_keys.request_keys(model)`（按配置顺序领取可用列表）或 `request_key(model)`（一个 Key）；发送前用 `is_available(key, model)` 检查。调用成功后 `report_success(key, model)`，失败后 `report_failure(key, model, http_status, retry_after, message)`。`message` 仅用于识别明确的失效原因，不落盘。明确无效的 Key 全局跳过；限流/模型权限按模型冷却，网络故障不当作 Key 失效。冷却自动到期，也可手动重置。模型参数仍由各功能管理。

后台反馈通过 Qt 排队信号交给主线程，合并后延迟保存；设置弹窗打开时暂缓自动写入，正常退出时保存。Key 编辑和启动不会发起验证请求，也不会重启模型。未来插件可直接复用此接口，不必把网络请求移到主窗口中。

插件可以注册四类扩展：

- `main_menu`：显示在主窗口的“插件”菜单中，也支持可勾选的开关命令；
- `tools_menu`：追加到主窗口现有的“工具”菜单中；
- `task_context_menu`：显示在任务列表右键菜单中，回调会收到选中行。宿主自动按插件分组为子菜单，优先保留命令的 `submenu` 标题，未指定时使用插件名称；不同插件的同名分组不会合并。隐藏／禁用插件不产生空菜单，插件无需自行添加分隔线；
- `PluginSettingsPage`：显示在“程序设置”中，由页面控制器负责加载、校验和保存配置。
- `PluginTabPage`：由主程序挂载到已有或新增的主界面标签页；插件只提供 QWidget，不直接修改主窗口布局。

插件生命周期为 `register(context) -> start() -> apply_settings(config) -> can_close() -> stop()`。主程序通过 `PluginContext` 提供日志、桌面通知、配置读写、选中任务行和安全的任务目录解析，不要求插件直接依赖 `MainDialog` 的内部字段。

需要读取当前登记表的插件使用 `context.current_task_table_path()`：返回主程序已加载项目的登记表路径（沿用配置中的文件名），未加载时返回 `None`。不要自行从当前日期控件推算路径，也不要让用户重复选择同一张表；表格实际读取应放到工作线程。批量文案视频的“读取当前任务文案”和任务右键入口都复用此服务。

批量文案视频默认显示文本框边界及实际像素宽高；在预览中点击选择，拖动框内移动，拖动八个边角手柄缩放，Esc恢复本次拖动前的布局。位置页可切换百分比/当前导出画布像素，切换只改变读数、不修改布局；更换画布尺寸仍按比例适配。单位和边界显示偏好会保存，辅助线不会导出。

四角文字水印：图层 → 添加组件… → 四角水印…。这是独立封装对象，图层列表只显示一个“四角水印”，不会创建四个普通文本框。选中后在“水印设置 → 四角内容”分别填写，留空不显示；顶部选择要调整的角落，“角落样式”设置字体、描边、阴影、底色。“贴边位置”可选择四角贴边或自由定位，分别设置水平／垂直内缩，支持实际导出像素与各轴百分比换算；0 内缩使可见水印（含底色扩展、描边、阴影）贴到画面边缘。单位切换保持当前位置，可将贴边与内缩统一应用到四角，不覆盖内容和样式。新水印默认 12 px 内缩；旧配置保留自由位置，用户主动切换后才贴边。普通文本框的“位置”页也支持左／右、上／下的距离基准与“一键贴边”菜单；切换基准不移动原框，调整框宽高保留对应边距，拖拽继续按框中心数据回写，预览与渲染复用原排版。默认暖白字、细暗红描边，不使用黑字/黑框。整体开关、透明度、层级、删除和撤销按一个对象管理；按独立配置保存，预览与导出一致，重复添加只定位已有对象。旧版快捷入口创建的四个水印文本层自动合并并保留各自内容、位置及样式；留空保留样式便于重新启用。为统一为一个层级，迁移后的整个水印位于原最上方水印的位置。

任务绑定的文案视频成品名称使用主程序 `task_export_profiles` 的单视频候选名称模板；默认如 `2026年10月2日-reels.mp4`，输出仍在 `<日期>/<任务类型>/<任务编号>/`，不把编号混入 reels 名称。任务日期优先使用保存的完整日期、主界面已加载日期的年份或同项目既有成品年份，未使用导出当天的月日。旧的自动“编号_文字版”名称只在内存中更新，新导出使用标准名称；既有文件、完成状态、输出记录不改名或删除。手动改名和复制出的手动变体保留自定义名称，并提示可能不再被整理规则识别。文案池搭配到队列时保留任务日期等元数据；文件夹导入不会把已生成的标准成品当作背景。成品碰撞、源文件覆盖保护、正在写入的视频暂缓规则不变。

可变字体字重：读取Qt实际选中字形的OpenType `fvar` 表，识别 `wght` 范围，验证本机渲染后端确实能改变字形后按轴渲染，例如550、551无需落到Regular/Bold预设。内置官方Open Sans正体及斜体，支持300–800连续字重（400常规、700粗体），不依赖用户安装齐全的字体，也不安装系统字体或运行时联网下载；打包包含字体及原始OFL许可证。请选择“Open Sans”，不是固定字形名称“Open Sans ExtraBold”。超出范围时应用端点并明确显示，保留原始配置值；没有可变轴的静态字体继续使用现有字形。单档字体会说明当前资源只加载到一档，不据此断言整个字体家族没有其他字重。元数据读取失败或后端不支持时标注待确认/未应用，不悄悄假装调节成功。预览与导出共用解析与字体构造，元数据使用有界缓存，字体数据库变化时自动清除；无需新依赖或逐文件扫描。

预览区域下方的“播放预览”在后台生成低分辨率完整合成视频，包含当前文字、图片、人声、音乐和时长适配，使用已有mpv/Qt/FFplay播放器，不新增播放器依赖。支持播放/暂停和拖动进度条；“返回编辑”回到可拖动的首帧排版画面。第一次准备需要等待，再次播放复用缓存；修改文案/图层/参数或源文件后重建，不推进文案、图片或音乐轮换位置、不写入正式任务成品。切换配置或关闭窗口会停止播放及取消正在准备的预览。播放缓存最多12份、256MiB（保留当前文件，即使它独占超过上限），只清理自身生成的缓存文件。

“基础 → 背景模糊”支持0–40，0关闭；可先试4–10，按1080宽画布缩放。使用FFmpeg高斯模糊，仅模糊背景视频，之后再叠加文字和图片，因此它们保持清晰；静态预览、播放预览和正式导出均支持。默认0，旧配置不改变效果，参数随各独立配置保存。

各文本框的“排版”分为字体/描边/阴影/底色：字重可直接输入1–1000的整数，同时保留9档预设；支持加粗、斜体、下划线、删除线、大小写、字距/词距/段距。描边可调厚度（0关闭）、颜色和不透明度，新文本框默认暗红色（#8b0000），已有配置明确保存的颜色不改动；阴影可开关并调整颜色、不透明度及横纵偏移。颜色按钮带色块，圆角底色及内边距也独立调整。程序自带官方Poppins 100–900九档正体和斜体，仅在程序内加载、不安装系统字体。字重下方显示Qt实际选择的档位，悬停查看该字体已安装字重；缺档或Qt模拟粗体会明确提示。其他静态字体的区别仍取决于其字形，例如输入650可能实际选择600/700，但原始650不会被改写，也不使用描边伪造字重。预览与导出共享字形。字号和文字效果像素沿用1080宽基准；字体、字重和间距参与自适应测量，放不下仍阻止导出。背景叠色有暖金/冷蓝/复古棕/柔和粉预设，颜色与强度可自定义，只作用于视频背景，不染色上层图片和文字。

批量文案视频的“资源池”分为视频、文案、图片、音乐；导入资源不再追加空白生成任务。通过“资源”菜单读取当前登记表、导入或新增；表格选择窗口支持Ctrl/Shift多选、右键批量勾选及“仅导入高亮行”。通过“批量 → 搭配资源，加入生成队列”选择文案为主、视频为主、一对一或共用背景，先核对搭配表，可逐行换视频。重复应用同一文案＋视频复用原队列项，内容未变时保留已完成状态；不同背景版本用数字区分名称，不添加随机校验码。表格/人声任务始终导出到自己的任务目录。

资源池和生成队列都支持多选、右键移出、Delete、Ctrl+A、Alt+上下箭头排序及清空确认；这些操作只删除列表记录，绝不删除原文件或成品。移出池条目不会连带删除已搭配的队列。图片池保存导入副本，右键可加入固定图片图层或轮换图片框；音乐仍保留逐首播放位置。

“资源 → 新建资源池”可创建任意名称的独立池。先选视觉/听觉类别，再选图片（水印）、背景视频、背景音乐或人声用途；每个池一种用途，避免人声被音乐静音裁切/续播规则误处理。拖入文件或“添加文件到当前池”导入，支持右键、删除、排序、改名及删池。默认四个池保持兼容，自建池随当前配置独立保存，不复制/移动音视频原文件。

“批量 → 搭配资源”可选择自建背景视频池；人声可沿用任务绑定、不使用、从指定语音池依次轮换或共用第一条，并可逐行更换。人声从头完整播放，不裁停顿，输出长度沿用已有背景适配策略，表格任务目录不变。右键语音池也能将所选人声分配给所选队列或当前文案。“混音 → 背景音乐池”选择配乐来源（也可右键音乐池应用），EQ与说话时自动压低仍可调整；各音乐池单独保存续播位置，只有导出成功才推进，预览不消耗。

右键自建图片池可添加固定水印/图片图层或绑定该池的轮换图片框。已有图片控件也可在“图层 → 内容 → 选择 / 绑定图片池”中更换绑定，支持固定用一张或逐视频轮换；空池可预先绑定，添加图片后自动更新，但空池不能导出。删除池不删除素材、队列或成品；引用的图片框会保留为自定义轮换，正在使用的音乐池则切回默认池。背景视频池目前用于底层背景，不代表已支持叠加视频图层或绿幕抠像。

普通文本框使用手填文字，或从文案池选择一次固定文字；“轮换文本框（文案池）”自动循环读取池中的完整文案、标题或正文。“自定义轮换”继续兼容原序列配置。预览不消耗内容，取消和失败不推进，只有导出成功才保存下一项。池重排时尽量保持下一条的稳定编号。标题/正文预设仍可读取搭配任务自身的文案。

“配置”菜单支持保存、新建空配置、另存为（含资源清单和进度）、重命名和切换；配置名显示在窗口标题中。每套配置独立保存图层、资源池、队列及轮换位置，引用的原文件不会复制或移动。旧数据首次读取时仅补充池和默认配置，原队列与成品记录保留；移出的资源不会在重新打开后自动复活。

“视频提示词助手”位于主菜单的“插件”中。拖入图片后先用作者原句模板给出可编辑的通用动画方案；用户主动点击看图并同意上传缩小图后，才复用已有的 Gemini Key 识别画面类型、主体和文字存在与否，再选用对应模板。它只负责提示词，不操控视频生成网站，也不保存原图。成功案例（标题、成功文案、可选失败文案和备注）保存在 Git 忽略的 `VideoPromptAssistant/cases.json`，预留 `tags` 字段供后续扩展。

“智能文案分段助手”位于插件菜单；任务列表右键“智能文案分段”直接读取所选任务的 `task_audio_text`，支持多选批量。默认优先接近10秒并减少段数，末段可建议6或8秒，也可固定时长。句末/换行/逗号等停顿优先，兜底只在完整词之间切分；不改写、不翻译，不修改登记表。建议生成秒数与估计朗读分开显示；语速、停顿和每段预留可调整，并通过“保存默认参数”只更新 `script_segmenter` 配置节。中文等连续无空格文本不猜测词界；单个文本单元超时会标明，不能伪装成合格10秒段。支持Ctrl+C/右键复制、保存TXT到任务目录；窗口关闭隐藏，主程序后台任务继续，不需要API或本地模型。

新内置插件放在 `app_plugins/builtin/`，并在主窗口安装。插件 ID、命令 ID 和设置页 ID 必须稳定且唯一；需要更高接口版本时应声明 `required_api_version`，不能静默降级。

任务登记表的可选“语音ID”列现已启用（也识别“声音ID”“配音ID”“voice_id”，可在任务表格结构中改别名）。填写后优先使用指定ElevenLabs Voice ID与当前最新模型`eleven_v4`（2026-10-07官方文档），无需填写语音类型；未填时完全沿用原来的Edge/v2/v3配置。仅使用程序已有的ElevenLabs Key轮换与状态记录，不随机替换声音或悄悄降级模型。长文按完整词分成不超过2000字符的API请求，由现有FFmpeg合为一个音频，全部完成才保存；已有成品继续跳过，不覆盖，也不改变字幕选项。生成入口仍是主界面生成音频与任务右键“音频与字幕”。

“Facebook 视频分镜速览”在插件菜单中打开。粘贴 Facebook/Reels 链接后，插件用 yt-dlp 在后台临时获取可访问的视频，再以 OpenCV 检测硬切、黑场和短时渐变切换，用 Pillow 输出按时间排列的大图；也支持本地视频、灵敏度与最短镜头参数、手动增删切点并重新导出。登录受限视频可选择读取 Chrome/Edge 的现有登录状态，插件不保存密码或 Cookie 文件；因 Facebook 页面和访问权限会变化，不保证任意链接都可解析。下载缓存只在窗口存续期间使用，不写入项目目录。

## 主程序后台任务

`context.background_tasks` 是宿主持有的任务管理器；插件窗口不拥有工作线程。第一批接入 Facebook 参考大图，其他插件的旧线程不会自动迁移，也不会自动受到此队列的互斥保护。

在主线程提交普通数据快照，在工作线程执行纯业务函数，通过 `TaskRunContext.report()` 发进度、`check_canceled()` 响应取消。`completed` / `failed` / `finished` 信号回到主线程，才能修改控件、弹窗和调用需要主线程的宿主功能。运行函数不得捕获 QWidget、可变全局配置或共享模型；只读 Qt 对象也不能在工作线程随意访问。

```python
def make_reference(payload, run):
    run.report("开始处理", 0)
    run.check_canceled()
    # 执行耗时操作；网络和媒体辅助函数应传入 canceled=run.is_canceled。
    return {"paths": [payload["output_file"]]}

handle = context.submit_background_task(
    title="任务 239 · 参考大图", runner=make_reference,
    payload={"output_file": "/path/to/result.jpg"},
    kind="media", execution="parallel", resources=["directory:/path/to/output"],
    retryable=True,
)
handle.completed.connect(view.on_completed)
```

目录资源应使用 `model.BackgroundTasks.directory_resource(path)`，确保大小写和路径表达统一。资源键锁定声明的同一资源，不是系统级文件锁，也不是自动递归锁。所有共享写入方必须声明同一键；库存存储、密钥状态、提交日志已有的数据层锁仍需保留。写主配置、调用共享 Whisper / GPU 模型和修改同一文件等不能因为“多数只读”就忽略同步。

智能剪辑（2026-10-12）不再给所有分析／所有导出各套一把全局队列锁。不同输出目录可并行裁剪、合并、气口检测和缓存分析；同一任务输出目录仍整批锁定，防止报告覆盖、版本命名和重新分析冲突。Whisper 仅在实际识别／最终字幕对齐时独占，惰性识别迭代器须在锁内消费并关闭；SRT排版、文件保存和视频编码不持有模型锁。最终导出的共享模型按需在字幕对齐阶段加载，不在任务启动时加载，跳过／分段导出不加载模型。默认媒体并发2、总后台并发3未放大，避免多个 FFmpeg 自身多线程耗尽CPU/内存；任务卡明确区分“同一目录资源互斥”和“并发名额已满”。批量文案视频的音乐/资源池轮换账本、任务交付上传去重、库存事务及同目录写入仍保留原保护，不能只因每个视频独立就取消这些锁。

共享 Whisper 使用按线程先来先服务的等待票据；一批分析完成一个片段后，不能抢在已有等待者前再识别下一片段。等待可取消，异常会移除票据／释放模型；同线程嵌套仍可重入，避免内部复用造成死锁。只协调本进程的共享模型，不改变本地模型缓存、ASR结果、字幕参数或输出格式。

- `execution="parallel"`：遵循资源锁和并发配额；默认全局最多3项，network/media最多2项，cpu/model最多1项。
- `execution="exclusive"`：等前面的任务结束后独占此队列；后续任务不会越过它，不影响尚未接入管理器的旧后台线程。
- `dedup_key`：仅合并同插件的相同活动任务；完成后可以重新提交。
- `retryable=True`：只有确定可安全重复执行的任务才开放重试，付款、追加表格、删除／移动文件等不能默认重试。
- 取消是协作式的，不强杀线程。退出整软件时可选择完成后退出、安全取消后退出或继续使用；关闭插件窗口只是隐藏。
- `logs/background_tasks.json` 只保存任务元数据，七天／300条，不保存运行参数、密钥和 Cookie；诊断文本脱敏，单条历史堆栈最多20,000字符。异常退出的旧任务标记未完成，不自动重放可能产生写入的任务。
- 任务会在当前进程内继续执行；不是退出软件后还能执行的系统服务。

### 后台并发设置

入口：程序设置 → 程序设置分组 → 后台任务与并发。后台总并发、视频／媒体并发、联网并发均可设1–8，未配置时沿用3／2／2；“视频优先”按钮填写6／4／2，点击确定并保存成功后即时应用。实际同时运行数必须同时满足总数、类别数、插件资源锁和独占策略；调低上限不终止正在运行的任务，等数量下降后再调度。文案视频右侧“渲染队列”的最终编码路数是另一层跨项目名额，不能将二者混为一谈。

主配置字段为 `background_tasks.max_parallel`、`background_tasks.kind_limits.media` 与 `.network`，由主程序统一读取／保存；无效值拒绝应用，启动遇到无效记录时提示并采用安全默认，不悄悄改写文件。UI不开放CPU类通用脚本和模型类别并发，它们仍为1；即便手写相应字段也不能用此设置放开。字幕识别／对齐的细粒度共享模型锁、同一输出目录／资源锁及插件声明的互斥策略始终有效。新插件必须声明真实类别和冲突资源，不能因用户提高并发而省略必要锁。

`BackgroundTaskManager.apply_limits()` 只能在GUI线程调用，调整的是后续任务准入，不更改已运行任务的参数快照、不清空等待队列、不重新开启退出中的管理器。单独更改这一设置不调用所有插件的 `apply_settings()`，以免重启无关监视或模型。

## 插件数据读写规范

这是同进程可信插件的开发规范，不是 Hook、防火墙、沙箱或文件权限隔离。主配置继续使用 `context.load_config()`、`context.save_config()`／`patch_config()`，不另建一份配置。实际文件打开／创建、SQLite 连接、原子写入、临时文件、复制、移动和清理统一委托给 `model.AppDataStorage`；插件只负责业务格式、SQL、事务和校验。主程序提供的存储服务是普通线程安全代码，不要求把磁盘操作搬到 Qt 主线程。

新插件通过 `context.storage` 申请命名空间内的相对名称：

```python
file = context.storage.file("records/state.json")
with file.atomic_writer(encoding="utf-8") as handle:
    json.dump(payload, handle, ensure_ascii=False)
with file.open("r", encoding="utf-8") as handle:
    payload = json.load(handle)
db = context.storage.file("index.sqlite3").connect(timeout=20)
try:
    with db:
        db.execute("INSERT INTO records(name) VALUES (?)", (name,))
finally:
    db.close()
```

命名空间拒绝绝对路径、盘符、`..` 和 NTFS 替代数据流名称。文件句柄／连接不能放进后台任务 payload，也不能跨线程分享 SQLite 连接；先提交普通资源标识／已批准的位置，在实际工作线程向存储层请求句柄，完成后关闭。SQL 事务、锁和原有索引格式仍由对应业务模块维护；WAL／SHM 留在数据库旁边。

旧插件暂时使用 `data_file(path)`、`data_directory(path)` 和 `data_io` 的已审查位置适配器，保留原文件名、外部工具要求的路径、私有凭据权限和回滚流程；这次不迁移、重建或清空任何记录。原来的本地数据库与索引继续使用，不触发重新下载模型或重建索引。新代码不得借旧适配器随意另建持久数据目录，应由主程序登记资源位置。FFmpeg、Qt、Pillow 等只能接受路径的库可以使用主程序批准的位置，不要求把视频内容读进 Python 内存；原始素材、任务目录、任务表格和成品仍沿用现有业务授权。

`tests/test_plugin_storage_boundary.py` 检查插件源码中绕过服务的 `open`、Path 读写、`sqlite3.connect`、临时文件、复制／移动等明显调用；沿用发布流程的测试发现机制。它能防止无意回退，不能识别所有动态 Python 行为，不能约束恶意插件或第三方库的内部 I/O。原子写入失败保留旧文件，并清理同目录临时文件；不对损坏记录默默生成空默认值。

2026-10-13 接入可选的 VeraCrypt 强制数据模式。首次完成迁移后，每次启动必须通过驱动校验卷和数据身份，再设置 `app_paths.DATA_ROOT` 并初始化存储、日志与插件。`APP_ROOT` 始终表示代码/公共资源位置，不能随卷切换。当前验证 Windows VC 1.26.7，未知版本拒绝放行。

保护模式下 `context.storage`、`data_file`、`data_directory`、`data_io` 会在操作前核对卷身份、当前挂载代次、目录边界和空间；已有 Python 句柄和 SQLite 提交也检查。私有原位置与临时旁文件按迁移清单映射；WAL/SHM、应用临时目录、完整日志和附件在卷内。卷失效后状态锁定到本次进程结束，不能原地重绑，也不得捕获错误后自行用空配置或明文备用文件继续保存。相关 UI 必须捕获存储错误，不能让异常逃出 Qt 信号回调。

2026-10-16性能修订：驱动句柄在会话中保持打开，版本在建会话时核对；每次操作实时查询本卷属性及设备映射，不用TTL跳过失卷检查，也不为每条SQL重新枚举所有卷。身份标记持有只读且禁止写入／删除共享的句柄，退出释放；它不是可热编辑的业务文件。目录边界逐级lstat，拒绝所有重解析点及上级目录跳转。磁盘探测不持有全会话I/O锁，返回前再次核对失效锁存状态；容量检查和数据库执行仍分别在实际写入／执行前进行。

存储空间监测及配置热更新的定时文件探测在单个有界只读后台线程中进行，结果通过内存队列交给GUI；不向线程传入窗口，不在后台更新Qt对象，不把运行数据另写明文缓存。已有显式保存、原子替换、配置冲突检查与退出持久化仍沿用原流程；这次不将“用户点击保存”改成未完成就虚报成功的异步写入。

保持 `context.storage` 等服务在工作线程中按需获取，句柄/SQLite 连接仍不得跨线程分享。FFmpeg、Qt、OAuth SDK 等仅接受路径时，使用存储服务批准/解析的路径，并由调用方关闭子进程和句柄；不做全局文件 API Hook。第三方库内部 I/O、外部客户端活动配置、系统交换文件和强制卸载竞争窗口不由此规范彻底隔离。退出只释放本程序资源，不卸载用户手动挂载的卷。诊断自动上传未启用；如需提交日志，由用户解锁后自行选择脱敏内容。

### 导出终点与 Python 接手

“导出成品”及旧式结算导出节点只有输入端，没有可连线输出端。`NodeDefinition.terminal_result` 声明交给执行器的内部结果，必须为固定类型、必填单值，不能同时声明 `outputs`；画布、类型推导与接线只使用 `inputs` / `outputs`，不能把内部结果接到其他节点。构建阶段仍返回经检查的 `RenderPlan`，只编译计划，不提前生成或伪造文件。独立预览可展示内部计划，但不会完成成品导出。

实际媒体导出沿用 `render.run_workflow(payload, context, registry=registry)`。成功完成编码、媒体校验与成品发布后，返回普通 Python 字典，主要字段为 `video`（成品路径）、`paths`、`subtitles`、`report`、`duration`、`notes`、`seconds`；任务调用 `run_task_workflow` 还附带 `status`、`task_key`、`task_label`。字幕／报告不存在时字段为空，不伪造文件。可信 Python 调用方可在函数成功返回后做归档、改名或上传；取消和失败不能当成成功处理，渲染计划／临时路径不能当成成品。此变更不新增自动上传、不执行用户脚本文本，也不增加第二次编码。

### Begin / End 结构化循环

“节点 → 流程控制 → Begin · End 循环块 → 添加成对循环块”一次添加并连好 Begin/End。Begin 的循环块输出接 End 的配对输入，中间节点处理当前数据／当前项／索引，处理结果接 End 的本轮结果。后续节点必须从 End 输出接线，不能直接使用块内数据。无需回环线、Break 或 Continue。可嵌套，但不同循环块不能交叉引用。结构参考 [Houdini Block Begin/End](https://www.sidefx.com/docs/houdini/model/looping.html)，不是复制其源码。

Begin 的模式：按次数（For）、逐项遍历（For Each）和条件循环。按次数由 End 的参数或次数输入决定；逐项遍历连接普通列表，当前项输出不可变 Python 数据，可接现有 int/str/list 等转换节点。迭代索引从 0 开始，“第几次”从 1 开始，数值输出为起始值＋索引×步长。使用“当前数据”输出时要接初始数据；选上一轮反馈后，第一轮用初始数据，以后用 End 的上轮结果，反馈数据类型必须一致。条件循环是执行后判断：至少执行一轮，End 的停止条件为真时结束，为假时继续；不是 Python 的执行前 while 判断。

End 输出最终／最后一轮结果、结果集合和实际次数。收集模式保留每轮原顺序；“仅保留最终结果”适合反馈和大数据，结果集合只含最后一项。0 次／空列表不执行循环体，结果集合为空，只有初始数据与最终输出同类型时才透传初始数据，否则最后结果为空。结果集合接“循环结果 → Python 列表”进入原有 Python 节点，或接“循环结果 → 合并视频操作”把原插件生成的操作交给视频结算器。媒体引用不复制成 JSON，不在循环中编码中间视频；沿用原有最终渲染与资源签名检查。

循环在原后台任务里运行并支持取消。默认上限 1000 次，可调至 10000 次；按次数／列表长度超过上限在开始前报错，条件循环达到上限还没停止则失败，均不静默截断。总节点执行上限 100000 次、循环嵌套最多 16 层；收集的纯数据／计划元数据预算 8 MiB（不包括媒体会话已有压缩缓存），超过时提示改为仅保留最终结果。固定的块外上游每次任务只计算一次，依赖迭代数据的节点每轮重新计算。不同任务不共享运行缓存；节点的 prepare 与锁声明仍按原流程在提交前处理。

“文件 → 新建 Begin／End 循环示例”有平方、遍历列表和反馈累加三个无需素材即可执行的示例。独立预览节点接在块内时，先执行配对循环，再展示最后一次实际迭代的数据；0 次循环没有内部预览，应查看 End 输出。预览可能运行整个循环及模型分析，但不会执行下游成品导出。

循环区域背景自动包围 Begin、End 及两者之间实际连线经过的节点，包括停止条件与中间接点；块外常量、只连出但不回到 End 的分支及 End 后续节点不作为成员。范围只帮助查看，不改变执行器的依赖与迭代判断，也不会把碰巧放在色块内的外部节点变成循环体。嵌套循环使用分层颜色，拖动节点时更新；背景不拦截框选、端口点击、画布右键或中键平移。Begin/End 右键可“定位配对 Begin / End”；块内节点右键可查看整个循环范围或更改区域颜色。颜色存于工作流 JSON 的 Begin.appearance.loop_color，不写主程序配置，可撤销／重做。未连接输入为空心、已连接输入填色，形状仍遵循圆形必填、三角形可选和竖向多输入。

节点工作区：主程序“工作流 → 节点工作流”。画布按 Tab、空白处右键或“节点 → 查找／添加节点”打开可搜索目录；可搜中文、函数名、插件命名空间和注册的关键词。分类来自 `NodeDefinition.category`（`/` 分子分类），不需要主窗口逐个判断插件。旧节点没有分类时沿用原分类。路径处理、基础数值／布尔及文本节点继续保留，不创建第二套实现。

“节点 → Python 原生”统一收纳流程控制、逻辑与判断、数据与转换、列表、字典、字符串、数学、日期与网址八类。Begin／End 在“流程控制 → Begin · End 循环块”，二选一／多条件 Switch 和空值回退在“流程控制 → 条件分支”；原数值、布尔与文字节点移到对应子分类，节点 kind 和保存数据不变，旧工作流不需改接线。路径处理仍单独分类，媒体／插件业务不搬进 Python 分类。当前 `core.py_*` 共64个节点，另有复用原实现的基础节点。列表索引遵循 Python，从0开始，支持负数；切片不含结束索引。`range`不含结束值，`zip`以最短列表为准。数学节点含abs/round/floor/ceil/sqrt/log/三角函数等；类型转换必须显式进行，不能把JSON数据直接接到插件的文本或数值端口。`bool()`沿用Python规则：非空的`"false"`也是True，可用JSON布尔值避免误解。列表去重/计数/相等筛选区分文本、数值、布尔的实际类型，不把True当作1。

新增15个可组合的数据节点，不执行用户代码，不增加依赖或另一套执行器：

- 逻辑与判断：通用同类型比较（两路多态端口统一类型）、is None、是否为空、all/any 列表真假判断。大小比较只接受数值或文字；容器可比较内容，布尔不当作数值。all/any 默认严格布尔，可主动改为 Python 真假规则；空列表遵循 all=True、any=False。空值和空内容独立判断，0/False 不算空内容。
- 条件分支：空值回退仅对 JSON null 使用备用输入；0/False/空文字/空容器保留原值，备用分支只在需要时计算。两路均使用 Python 数据。原普通“条件选择”改为惰性二选一，与多条件 Switch 一样只计算选中分支；所有分支仍做静态接线、类型、参数／资源预检，`prepare` 和锁声明不因此跳过。这不是禁止副作用的沙箱。
- 列表：追加／插入／替换、移除并取出、按数量分批、指定层数展开、提取字典字段、按字段稳定排序、按文字字段分组。分批保留最后不足一批的余项，可接 Begin 的 For Each；默认缺字段、索引越界或排序类型混用报错。跳过缺字段必须明确选择。修改节点返回新列表，不修改源数据或删除文件。
- 字典：从键值对创建（默认重复键报错），读取嵌套字段（如 `["items",0,"name"]`，路径可接列表输入，支持负索引，返回 found 与 Python 数据；实际 null 的 found=True）。不提供任意对象属性访问。
- 字符串：安全字段模板，如 `${date}-${name}.mp4`，字段字典接输入；`$$` 表示文字美元符号。只替换简单字段，缺字段报错，展开前限制大小，不执行表达式。

“文件 → 新建 Python 批量分组示例”可直接执行：JSON 字典列表 → 按编号排序 → 按管理员分组 → 数据输出。另保留原列表筛选与三种 Begin／End 示例。没有加入用户暂不需要的 break/continue，也没有让循环生成中间视频文件。

“文件 → 新建 Python 数据处理示例”可直接运行列表筛选演示。“数据输出 → 查看结果”是Detail纯数据流程的终点，普通值先用“Python 数据 → 包装值”连接；执行后打开数据结果窗口，不依赖FFmpeg、不写成品、不上传数据。中间节点仍可接独立预览。Line任务的视频流程继续以媒体导出结束，Python节点在其中作为数据处理步骤使用。

`Python 数据`端口使用不可变JSON快照，null不会被当成“缺少媒体”。列表和字典是有界的普通数据，分支之间复制，不能通过改列表污染另一分支。只允许文本、有限数值、布尔、null、列表和文本键字典；拒绝循环引用、任意对象、重复JSON键和NaN/Infinity。数据上限1MiB、100000项、32层，超限报错而不是悄悄截断。预览显示截断会注明，不截断实际数据。字典／列表取值输出Python数据，后续用str/int/float/bool/list/dict转换接回现有插件。

与媒体插件的桥接：`listdir → 文件列表→Python路径列表 → 列表筛选／排序／切片 → Python路径列表→文件列表 → 智能剪辑`。最后的桥接同时接原文件列表，只允许选取、重排原列表内的文件，保留目录归属、大小和修改时间；拒绝新增路径和重复文件。这样不会绕过任务／资源快照检查。

画布“编辑”菜单支持Ctrl+Z撤销、Ctrl+Y或Ctrl+Shift+Z重做：添加、删除、连线、接点、参数、移动、类型及连线样式。一次多节点拖动保存所有选中节点的位置；连续修改同一参数短时间合并。最多100步，历史仅为当前工作区内存中的压缩数据，不写入配置/工作流文件，不保留Qt控件或工作线程，也不会撤销已经导出的文件。打开／新建工作流重置历史，保存设置清洁点。

普通添加节点以及添加成对 Begin／End 现在直接增量加入现有画布，不重建已有节点，不寻找空位、不自动重排、不适应视图。新节点放在指定位置（菜单添加默认视口中心），重叠时在最上层，可直接点击拖开；堆叠顺序保存在 appearance.stack_order。原节点对象、位置、连线及视角保持不变。撤销、改变动态端口等仍可按需重建画布，不改变用户保存的位置。

“节点 → 插件处理 → 视频拼接 → 视频拼接 · 左右”复用视频拼接插件：左右两个必填视频端，一个视频流输出。可选左／右时长和帧率基准、基准声音／左声／右声／混音／静音，以及兼容偶数尺寸／严格原尺寸。宽度相加、高度取较大值，较矮一侧居中补黑边；非基准侧短则循环、长则截断。可接文件、无损内存传输、智能剪辑计划、已有图层视频流以及嵌套拼接；不接任意 Python 数据或网络地址。它构建 VideoComposition 声明式源计划，尺寸、循环与音频算法由原插件的 make_plan/composition_filters 共用。最终预览和导出把两路解码、已有图层／字幕、拼接及后续效果编译进同一个 FFmpeg 过滤器图，只有最终一次视频编码，不产生中间 MP4。内部仍可能生成字幕、图层 PNG 和过滤器文本等小型临时资源。

拼接不提供文件名输入或自行保存成品；接视频结算／预览／压缩／导出或任务交付专用输出继续使用。仅缓存了有原文件的无损媒体可恢复原引用参与拼接；没有可定位原文件的任意外部流生产者目前会明确报错，不会悄悄落地。两个不同的已绑定任务身份不能混合；全局导入的不带任务身份素材可搭配任务视频。循环／嵌套编译有16层、128媒体输入和256轮的上限，超限报错，不静默截断。

插件如要提供多视频源处理，可在 NodeDefinition 声明 compile_source 可信回调，返回公共 SourceStage，使用 SourceBuilder 构建子视频输入；普通图层仍使用 compile_operation。保存的工作流只记录节点参数和接线，不记录编译函数或执行句柄。插件被禁用或缺失源编译器时不能运行其合成计划；这不属于运行不可信插件的沙箱。

借鉴来源：[NodeGraphQt](https://github.com/jchanvfx/NodeGraphQt)（MIT）的界面／数据分离和Qt命令撤销结构，以及[PyFlow函数库](https://github.com/pedroCabrera/PyFlow/blob/master/PyFlow/Core/FunctionLibrary.py)（Apache-2.0）的函数注册思路。这里是本程序接口下的独立实现，未复制或分发它们的源码，也未接入其他执行引擎。2026-10-11 隔离验证 NodeGraphQt 0.6.44＋Qt.py 2.0.7＋PyQt6 6.11.0：直接导入在 `QGraphicsItem.DeviceCoordinateCache` 报错；补齐源码实际使用的 85 个旧枚举别名后，节点创建、接线、Backdrop 分组、横竖布局／连线样式、撤销重做、会话保存恢复、鼠标平移和绘制的基础测试通过。这说明兼容问题可修，不应凭最初导入错误否定这个库。当前未安装生产依赖、未更换画布，也没有验证其全部控件／子图／平台组合。以后接管画布仍须适配端口几何、类型约束、插件编辑器、工作流格式和生命周期；它是 UI 框架，不会自动替代本程序的媒体对象、prepare、锁及后台执行逻辑。

插件可直接把可信函数注册成节点，不必依赖其他插件内部模块：

```python
from app_plugins.api import NodePort, NodeParameter, node_function

@node_function(
    kind="my_plugin.prefix", title="添加前缀",
    inputs=(NodePort("text", "文本", "text"),),
    outputs=(NodePort("text", "文本", "text"),),
    parameters=(NodeParameter("prefix", "前缀", default=""),),
    category="我的插件/文本", keywords=("prefix", "前缀"),
)
def prefix(text, prefix):
    return prefix + text

# 在插件register(context)中：
context.register_function(prefix)
```

函数的参数名与输入／参数key一致；单输出返回值本身，多输出返回输出key完全一致的字典。装饰器不改变原函数的调用方式，注册时核对签名与插件命名空间，运行时沿用现有类型检查、取消与后台执行逻辑。需要模型、prepare、视频操作编译器或专用UI的业务节点仍用`context.register_node(NodeDefinition(...))`。保存文件只记录节点kind/version/普通参数，不记录函数、导入路径或可执行脚本；未提供eval/exec、任意import或从工作流自动安装包的节点。函数运行在原工作线程，不属于安全沙箱，安装的插件代码必须可信。

### 多条件选择与预览反馈（2026-10-12）

文本框“样式 → 底色”保留整框底色，增加“随文字底色（字符模式）”：按实际排版后的每行文字宽度生成圆角底色，跟随自动换行、横向对齐、大小写和字体；竖排则跟随每列。不在单个字符之间切出小方块。四个方向可分别扩展0–300参考像素（按1080宽画布换算），只扩展底色，不改变字号、文字位置或换行；原内边距仍用于改变排版空间。可连接相邻行／列，较大段落空隙保留；半透明重叠底色只绘制一次，不额外变深。普通、滚动文本框及添加文字节点共用代码；滚动模式底色跟随文字移动并按窗口范围裁切，扩展不改变滚动速度和文字起止位置。动态字幕保留其预设底色，新选项明确禁用。旧配置默认整框、四方向0，不修改原文或资源池。

文案视频的播放预览现在按正式导出画布排版、合成，最后才缩小播放文件；不会因缩小后字体像素取整而改变字号和换行。旧播放缓存自动失效。“基础 → 画面 → 铺满导出画布”默认开启“自动去除素材自带黑边”：用 FFmpeg 在最多五个时间位置检查，只去除稳定、近对称的两侧黑边，再铺满画布。暗场景或艺术黑框可关闭；完整显示不自动裁边。检测结果按原文件路径、大小、修改时间缓存（最多256条），原素材不修改。首帧、播放预览、导出和叠化循环共用画幅处理；切换画布/铺满立即更新背景，不显示旧的带黑边缩略图。设计视图亮边框内才是导出画布，软件窗口外侧空白不写入视频。

文案视频“时长适配 → 无人声时长度 → 统一固定时长”可设置15秒或其他时长。默认保持原素材长度；固定模式复用原循环／叠化／减速／混合策略，长素材截短，短素材补足。启用人声时仍跟随实际人声长度，不因固定值裁掉朗读。保留背景原声时随画面变速／循环，原声不参与循环交界叠化；原人声EQ／压低音乐逻辑不变。

普通／滚动文本框“样式 → 颜色”增加同色系随机：基准色的色相±0–30度、饱和度和明暗±0–30百分点，默认固定颜色不改变。白／灰只变化明暗，描边和阴影独立。每条合成按背景路径、任务目录、文案和图层编号确定配色，不依赖临时播放目录、队列UUID或逐帧随机；预览、快速导出、批量、重试一致。“换一组颜色”改变颜色组编号，可保存、撤销，不消耗资源池。运行时只使用副本，不把随机结果覆盖基准色；添加文字节点也复用该功能并按全局当前循环次数区分。

“样式 → 字体 → 大小写 → 全部大写”已有，无需新增；Qt显示转换保留原文。用斯洛伐克语 á ä č ď é í ĺ ľ ň ó ô ŕ š ť ú ý ž 对照显式大写文本验证横排和竖排，预览／导出共用字形绘制。

视觉元素“视觉效果 → 叠加与抠像”支持绿幕、蓝幕、黑幕。“扣像透明度修正”的左下／右上端可直接拖动：提高左端清理半透明背景，降低右端恢复前景不透明；中间线性过渡。也可填两端百分比，必须左端小于右端；重置为 0 → 100 保持原扣像效果。使用同一组件的节点、文案视频设计视图、播放预览与导出共用此设置。修正在缩放与图层不透明度之前执行，FFmpeg 采用仅修改 Alpha 的 LUT，不在 Python 中逐帧处理或生成额外中间视频。另保留并乘回素材原生 Alpha，避免 FFmpeg colorkey 覆盖原透明通道，使本来透明的 PNG/GIF/MOV 区域重新出现；只在灰度蒙版上相乘，不额外处理 RGB。

黑幕按 RGB 距离去除近黑色，也可能去除前景黑色部分，建议先降低颜色容差；抑制绿／蓝溢色不用于黑幕。滤色适合火花／光效，黑色不影响背景但会让非黑部分变亮，不等同于黑幕扣像。扣像两端无法救回已经扣成完全透明的前景，需先降低颜色容差；过度压缩过渡范围可能引起硬边。

### AI调用节点（2026-10-14）

- 入口：节点面板添加节点 → **AI → AI调用**。由AI模型试用台插件注册，禁用该插件会禁用它的节点。选择服务商，填写与试用台一致的具体模型ID，密钥沿用“AI模型试用台 → 连接设置”。没有新密钥字段，不清空、迁移或轮换现有Key。
- 输入：可选“提示词／系统指令”覆盖参数，明确接入的“待处理文字”，最多3张本地图片（文件列表＋单张路径合计）。不扫描目录、不下载网址、不带历史对话、不隐式上传任务其他字段。图片共用聊天附件的解码、2048像素缩放、32MB源大小和3MB单张请求限制；模型不支持图片时沿用客户端明确报错。
- 输出：“回答文本”可接**添加文字 → 文字**，或接专用预览节点；“回答数据”是Python数据，文本模式封装为字符串，JSON模式严格解析一个JSON值（可接受完整JSON代码围栏），拒绝重复键、NaN和解释性杂文。另有“模型／用量报告”“复用缓存”“实际模型ID”。没有字段Schema约束；需用后续数据节点检查业务字段。不会把回答自动作为Python代码执行。
- 例：文案视频输入的正文 → AI调用的待处理文字；AI回答文本 → 添加文字的文字 → 返回视频操作。Line逐行独立接入文案，Detail可用固定文字或其他文本节点；AI只是计算节点，不改变现有导出终点和审核流程。仅接线的数据参与请求／缓存，不接入任务编号就不会自动把它发给模型。
- 编辑、移动、选择节点没有请求。普通预览、纯色模拟及文案视频**播放预览**默认只复用已有回答缓存；无缓存明确提示，不静默调用AI。若确需测试，可打开节点“允许预览联网”，包括自动刷新在内都可能消耗额度；静态编辑首帧仍不执行节点。正式执行默认可联网，离线模式只允许缓存命中。
- 缓存默认开启：主程序私有命名空间 `PluginData/ai_model_client/workflow_cache/answers.sqlite3`，回答由Windows当前用户DPAPI加密后才写入SQLite，VC模式仍由存储服务检查卷身份；缓存不含Key或原始请求，键是请求内容、图片、服务商、模型、生成参数、缓存版本及格式的摘要。上限256项／64MB加密载荷，旧项自动淘汰；更换缓存版本号可重新生成。此缓存不是唯一数据备份，换Windows用户可能无法解密；损坏时不自动删掉并重发收费请求。JSON校验失败、空回答、取消不作为成功缓存。
- 每服务商最多2个节点请求并发，相同请求合并等待后复用缓存，等待可取消；不锁住整个渲染。默认额外重试0，可选0–2，只有429／502／503／504且等待不超过10秒才有限重试，不重试401／403、余额错误或不明超时，不换平台／模型。生成调用上限1–100（默认20）按一次工作流上下文累计，含重试；**Line每行独立**，不是整个批次总预算。客户端可能另做一次模型目录查询GET，此次数上限不计算目录查询。输出Token上限128–32768，服务商仍可能有自己的限制。
- “仅免费／每日额度模型”复用客户端OpenRouter／Cloudflare策略，不代表有Key就免费，CF付费账户超额度可计费。元数据为客户端返回的服务报告，不是账单；部分服务未返回用量时不能据零值认定未消耗。连接快照仅存在宿主内存，排队超过24小时或重启后应重新提交，不在工作流JSON或普通后台payload放Key。HTTP沿用10秒连接／60秒读取超时，取消在网络阻塞读期间可能要等最多一次读取超时，不能承诺瞬时中止或退款。
- 开发接口：`context.ai_workflows`是宿主纯服务，`prepare_ai_workflow(provider)`只能主线程调用并返回不透明会话引用；工作线程只使用注册回调捕获的纯服务，不调用窗口、读取UI当前行或保存配置。没有新增生产依赖、文件API Hook、真实模型调用或发布动作。

### 文案视频字幕对齐与随机大小（2026-10-13）

- 精确模型模式直接对齐所选任务原文，不再用会重写标点／缩写的分句函数预处理；使用NFC等价校验，保留大小写、变音符、数字和全部词。模型的子词／单独标点按原文完整单词合并。文字缺失或时间异常先自动重试一次（最大上下文、关闭静音压缩），不把模型结果错误等同于音频损坏。
- 重试后最多连续2个、总体5%（至少允许2个）内部零时长词，且具备两侧有效锚点时，才允许30–80ms的局部近似修整并写明提示；不推算未对齐的大段内容。短窗口策略下，单个不超过3字母的开头／末尾词若紧邻有效词且处于另行核对的语句窗口，可借用最多80ms修整；不是放宽连续漏词／尾段失败限制。失败不会发布缓存或删词，也不会静默切换匀速动画。直接使用已有SRT的模式不做这类修整；原健康缓存核对全文后复用。无法保证任意文案和音频都能精确强制对齐。
- 整段与长上下文重试仍异常时，追加短窗口逐词重对齐。先核对实际人声同名SRT的全文和时长，把相邻小块合成不超过12秒左右的真实语句窗口；调用既有stable-ts `align_words`，重新从音频计算每个词的时间，不使用均分词时刻、不修改原SRT。不匹配、损坏、重叠或过长的SRT不能充当锚点；改由同一模型本地识别定位，至少65%的原文词需有连续可靠匹配，首尾和中间跨度均受约束；识别文字绝不替代原文，缺词／大面积零时长仍拒绝。所有处理复用模型锁与取消检查；缓存会保留短窗口和局部近似提示。
- 选中字幕组件→“字幕动画”分页→“随机字号对比度”。1×原有均匀随机、0×范围中点、2–3×强化大小差异、最高4×；大小仍在现有最小／最大范围内。图库随机大小还受“效果参数”的最小／最大倍数影响，较小字幕框会自适应压缩差异。该参数不参与语音对齐缓存，不会因为改字号效果而重新加载模型；节点与播放／最终导出复用同一渲染代码。
- 参考本机已安装 [stable-ts 官方 align 文档／源码](https://github.com/jianfch/stable-ts/blob/main/stable_whisper/alignment.py)：零时长词是对齐库可能返回的结果，不是音频损坏证据。本次未升级依赖。

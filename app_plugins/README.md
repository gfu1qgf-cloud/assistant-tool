# 应用插件接口

当前插件接口版本为 `1`。内置插件由主程序显式安装，暂不从任意目录自动执行第三方 Python 文件，避免未知代码在启动时获得业务配置和本地文件权限。

## 做饭小助手

“做饭小助手”从“插件 → 做饭小助手…”打开，包含食材库存和中文做饭方案。默认 1 人做 2 顿，调料仅默认勾选盐。配置页为“程序设置 → 做饭小助手”，独立配置键 `cooking_assistant`，默认模型为已核对官方文档的 `gemini-3.8-flash`，可改模型名；不影响其他功能的模型选择。菜谱使用主程序共享 Gemini Key，后台生成且反馈密钥状态，不加载本地模型或新增依赖。

库存、界面偏好、最近方案与最多 30 份缓存保存在 Git 忽略的 `CookingAssistant/food.sqlite3`。同批食材同一天复用缓存，点“换一组”才重新联网。生成菜谱不扣库存，用户通过“用掉／减量”确认使用量；同一种食材可分批登记。自己设置的检查日与包装 use-by / best before 分开标注，待核查、超过日期或变质条目不自动推荐；程序运行时对临期/待处理食材每日提醒。日期提醒不能判断实际新鲜度，不要擅自延长包装食用截止日。

菜谱为 AI 生成而非复制菜谱网站。库存管理离线可用；只有用户生成时发送所选食材、调料、人数及偏好。剩菜、米饭与日期标签的固定安全说明附官方 FSA/GOV.UK 链接（2026-10-01 核对），不依赖模型自由生成。程序关闭时不销毁仍在工作的 QThread，窗口关闭仅隐藏并保留状态。

## 共享 Gemini 密钥

主程序持有 Gemini Key，管理入口为“程序设置 → AI 密钥”，也可从“工具 → AI 密钥管理 · Gemini…”打开。旧配置的 `gemini_api_keys` 原样兼容；插件不能再维护或回写一份 Key 副本。可用状态保存在主配置的 `gemini_api_key_statuses`，以 Key 指纹索引，不保存原始错误响应。

插件可在后台线程使用 `context.gemini_keys.request_keys(model)`（按配置顺序领取可用列表）或 `request_key(model)`（一个 Key）；发送前用 `is_available(key, model)` 检查。调用成功后 `report_success(key, model)`，失败后 `report_failure(key, model, http_status, retry_after, message)`。`message` 仅用于识别明确的失效原因，不落盘。明确无效的 Key 全局跳过；限流/模型权限按模型冷却，网络故障不当作 Key 失效。冷却自动到期，也可手动重置。模型参数仍由各功能管理。

后台反馈通过 Qt 排队信号交给主线程，合并后延迟保存；设置弹窗打开时暂缓自动写入，正常退出时保存。Key 编辑和启动不会发起验证请求，也不会重启模型。未来插件可直接复用此接口，不必把网络请求移到主窗口中。

插件可以注册四类扩展：

- `main_menu`：显示在主窗口的“插件”菜单中，也支持可勾选的开关命令；
- `tools_menu`：追加到主窗口现有的“工具”菜单中；
- `task_context_menu`：显示在任务列表右键菜单中，回调会收到选中行；
- `PluginSettingsPage`：显示在“程序设置”中，由页面控制器负责加载、校验和保存配置。
- `PluginTabPage`：由主程序挂载到已有或新增的主界面标签页；插件只提供 QWidget，不直接修改主窗口布局。

插件生命周期为 `register(context) -> start() -> apply_settings(config) -> can_close() -> stop()`。主程序通过 `PluginContext` 提供日志、桌面通知、配置读写、选中任务行和安全的任务目录解析，不要求插件直接依赖 `MainDialog` 的内部字段。

需要读取当前登记表的插件使用 `context.current_task_table_path()`：返回主程序已加载项目的登记表路径（沿用配置中的文件名），未加载时返回 `None`。不要自行从当前日期控件推算路径，也不要让用户重复选择同一张表；表格实际读取应放到工作线程。批量文案视频的“读取当前任务文案”和任务右键入口都复用此服务。

批量文案视频默认显示文本框边界及实际像素宽高；在预览中点击选择，拖动框内移动，拖动八个边角手柄缩放，Esc恢复本次拖动前的布局。位置页可切换百分比/当前导出画布像素，切换只改变读数、不修改布局；更换画布尺寸仍按比例适配。单位和边界显示偏好会保存，辅助线不会导出。

预览区域下方的“播放预览”在后台生成低分辨率完整合成视频，包含当前文字、图片、人声、音乐和时长适配，使用已有mpv/Qt/FFplay播放器，不新增播放器依赖。支持播放/暂停和拖动进度条；“返回编辑”回到可拖动的首帧排版画面。第一次准备需要等待，再次播放复用缓存；修改文案/图层/参数或源文件后重建，不推进文案、图片或音乐轮换位置、不写入正式任务成品。切换配置或关闭窗口会停止播放及取消正在准备的预览。播放缓存最多12份、256MiB（保留当前文件，即使它独占超过上限），只清理自身生成的缓存文件。

“基础 → 背景模糊”支持0–40，0关闭；可先试4–10，按1080宽画布缩放。使用FFmpeg高斯模糊，仅模糊背景视频，之后再叠加文字和图片，因此它们保持清晰；静态预览、播放预览和正式导出均支持。默认0，旧配置不改变效果，参数随各独立配置保存。

各文本框的“排版”分为字体/描边/阴影/底色：字重可直接输入1–1000的整数，同时保留9档预设；支持加粗、斜体、下划线、删除线、大小写、字距/词距/段距。描边可调厚度（0关闭）、颜色和不透明度，新文本框默认暗红色（#8b0000），已有配置明确保存的颜色不改动；阴影可开关并调整颜色、不透明度及横纵偏移。颜色按钮带色块，圆角底色及内边距也独立调整。字重的实际区别取决于字体提供的字形，不会把自定义数值取整到预设。字号和文字效果像素沿用1080宽基准；字体、字重和间距参与自适应测量，放不下仍阻止导出。背景叠色有暖金/冷蓝/复古棕/柔和粉预设，颜色与强度可自定义，只作用于视频背景，不染色上层图片和文字。

批量文案视频的“资源池”分为视频、文案、图片、音乐；导入资源不再追加空白生成任务。通过“资源”菜单读取当前登记表、导入或新增；表格选择窗口支持Ctrl/Shift多选、右键批量勾选及“仅导入高亮行”。通过“批量 → 搭配资源，加入生成队列”选择文案为主、视频为主、一对一或共用背景，先核对搭配表，可逐行换视频。重复应用同一文案＋视频复用原队列项，内容未变时保留已完成状态；不同背景版本用数字区分名称，不添加随机校验码。表格/人声任务始终导出到自己的任务目录。

资源池和生成队列都支持多选、右键移出、Delete、Ctrl+A、Alt+上下箭头排序及清空确认；这些操作只删除列表记录，绝不删除原文件或成品。移出池条目不会连带删除已搭配的队列。图片池保存导入副本，右键可加入固定图片图层或轮换图片框；音乐仍保留逐首播放位置。

普通文本框使用手填文字，或从文案池选择一次固定文字；“轮换文本框（文案池）”自动循环读取池中的完整文案、标题或正文。“自定义轮换”继续兼容原序列配置。预览不消耗内容，取消和失败不推进，只有导出成功才保存下一项。池重排时尽量保持下一条的稳定编号。标题/正文预设仍可读取搭配任务自身的文案。

“配置”菜单支持保存、新建空配置、另存为（含资源清单和进度）、重命名和切换；配置名显示在窗口标题中。每套配置独立保存图层、资源池、队列及轮换位置，引用的原文件不会复制或移动。旧数据首次读取时仅补充池和默认配置，原队列与成品记录保留；移出的资源不会在重新打开后自动复活。

“视频提示词助手”位于主菜单的“插件”中。拖入图片后先用作者原句模板给出可编辑的通用动画方案；用户主动点击看图并同意上传缩小图后，才复用已有的 Gemini Key 识别画面类型、主体和文字存在与否，再选用对应模板。它只负责提示词，不操控视频生成网站，也不保存原图。成功案例（标题、成功文案、可选失败文案和备注）保存在 Git 忽略的 `VideoPromptAssistant/cases.json`，预留 `tags` 字段供后续扩展。

新内置插件放在 `app_plugins/builtin/`，并在主窗口安装。插件 ID、命令 ID 和设置页 ID 必须稳定且唯一；需要更高接口版本时应声明 `required_api_version`，不能静默降级。

“Facebook 视频分镜速览”在插件菜单中打开。粘贴 Facebook/Reels 链接后，插件用 yt-dlp 在后台临时获取可访问的视频，再以 OpenCV 检测硬切、黑场和短时渐变切换，用 Pillow 输出按时间排列的大图；也支持本地视频、灵敏度与最短镜头参数、手动增删切点并重新导出。登录受限视频可选择读取 Chrome/Edge 的现有登录状态，插件不保存密码或 Cookie 文件；因 Facebook 页面和访问权限会变化，不保证任意链接都可解析。下载缓存只在窗口存续期间使用，不写入项目目录。

任务列表右键分为“生成 Facebook 参考大图”和“查看 Facebook 参考大图”：前者可以多选任务，将每个任务的所有 Facebook 链接按顺序加入后台队列，已缓存的跳过，单条失败不会中断后续任务；后者只打开已生成的本地大图，不访问 Facebook。链接来自任务表 `task_reference_link`（含 ODS 单元格超链接），大图及 `manifest.json` 存在对应任务目录的 `Facebook参考大图/<视频标识>/` 中。多个已生成的参考链接可选择查看；没有可识别的链接或本地大图时会提示。任务参考仅缓存分镜大图，原视频只在生成期间临时存放。

当前内置插件包括库存与素材管理、图片智能分类、Chrome 启动器、切分音频和智能剪辑。图片智能分类插件通过后台懒加载 CLIP 模型先生成可人工修改的分类预览，再由用户确认复制或移动；设置保存在 `image_classifier_settings`，模型不得在程序启动阶段加载。切分音频插件在任务右键菜单中处理所选任务目录，并在“工具”菜单提供支持文件/文件夹拖拽的批量窗口；参数统一保存到 `audio_splitter` 配置节。Chrome 插件只接管窗口生命周期、菜单入口和全局快捷键；继续使用历史配置键 `chrome_preset_websites`、`chrome_profile_groups`、`chrome_profile_iterator` 和 `chrome_next_global_hotkey`，升级时不得清空或另建平行配置。

“智能搜图”插件索引库存管理、人物素材和在插件设置中指定的额外图片库文件夹，不复制原图，并递归读取子目录。首次使用时后台加载固定版本的中文 CLIP 安全权重；之后用文件大小和纳秒修改时间增量计算，路径、缩略图和特征缓存在本机 `SmartImageSearch/`（Git 忽略）。图片移出后立即注销对应索引项，不重算其他图片。配置键为 `smart_image_search`；更换模型版本必须重新生成该版本的特征。插件启动阶段不扫描图片、不加载模型。

“智能搜音乐”插件默认只读扫描 `D:\2.配乐库`，目录可在设置中修改。点击“增量更新索引”时才下载并加载固定版本的 LAION 音乐 CLAP 安全权重，用 FFmpeg 为每首音乐提取最多 8 段代表性片段；之后仅对大小或纳秒修改时间变化的文件重建索引。中文查询首次使用时在本机下载并运行固定版本的中英翻译安全权重，不调用在线翻译 API。SQLite 特征保存在 Git 忽略的 `SmartMusicSearch/` 中，原歌曲不会移动、重命名或上传。视频时长可手填或拖入视频读取，搜索时默认排除短于视频的曲目；勾选“也显示短曲”后才列出需循环使用的曲目。插件配置键为 `smart_music_search`，模型不在启动时加载。片段向量匹配只给出候选和试听起点，不保证整首歌曲的情绪始终一致，使用前需试听。

检索时会对文本和音频特征做去公共背景分量的对比评分；该计算只影响排序，不修改已有音频索引，因此升级后无需重新建库。

搜图覆盖当前索引内的全部可用图片，并按 `result_limit` 每批展示，默认每批 100 张；该设置不再截断总结果。界面会分别显示首次模型加载、条件编码和索引检索的耗时，缩略图按原始宽高比居中呈现。

缩略图缓存使用版本化的高清文件（最大 400×600，适合竖图预览）。旧缓存会在后台增量扫描时升级，但不重新计算模型特征；模型索引及原图保持不变。

搜索结果支持选中多图后拖到资源管理器，默认提出移动，按 Ctrl 可复制。只有目标确认移动后才移除原图及对应索引；Windows 的 `TargetMoveAction` 由目标自行移动，来源不重复删除。

智能剪辑插件拥有分析/导出线程、核对窗口、待处理记录和设置页。宿主只提供任务路径、字幕参数、共享 Whisper 模型与日志服务；历史配置键 `smart_video_editor`、`smart_video_pending_reviews` 以及旧的 `model.SmartVideoEditor`、`PYUI.smart_video_editor_pyui` 导入路径继续兼容。

达芬奇遥控器通过 `PluginTabPage` 复用主界面的遥控器标签。三个旧脚本的处理函数保存在 `davinci_legacy/`，其 Fusion UI 入口不由软件调用；插件用 PyQt 显示参数、进度与字幕异常列表，并通过 `main.py --davinci-worker` 在独立进程连接当前 Resolve。达芬奇和当前项目/时间线必须处于可用状态。对轨道清空、添加水印、自动渲染等可能改变时间线或任务队列的操作，界面会先确认。
